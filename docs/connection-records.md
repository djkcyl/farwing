# 连接记录与账号记录

网页端“记录”页与客户端侧栏“记录”页列出本账号的连接记录和账号记录；设备详情页列出这台设备的连接记录；管理员在“连接记录”页看全部，在账号详情页看某个账号的。记录保存在服务端，保留期与审计日志相同（“服务器设置 → 账号与网页端 → 审计日志与连接记录保留”，默认 180 天）。

## 一、连接记录

一条记录是一次连接：主控的一个观看窗口（或一次文件、端口转发会话）从第一次被接入到结束，中途断线重连仍是同一条（“重连 N 次”）。没被接入的尝试也各记一条。

| 内容 | 来源 |
| --- | --- |
| 谁连了哪台设备：双方设备名、主控的账号（访客没有账号）、关系（本账号、好友、访客、受信任设备）、访客怎样被接入（访问码、本机确认、访问码 + 本机确认） | 服务器 |
| 用途（远程桌面、声音、文件、端口转发），客户端还是网页端 | 服务器 |
| 开始、结束、时长、结束原因（主控断开、被控结束、被控离线、被新的连接取代、权限被收回、登录被移除、服务器重启等） | 服务器 |
| 主控的来源 IP（服务器看到的地址） | 服务器 |
| 没被接入的尝试：对方拒绝、无人确认、人数已满 | 服务器 |
| 实际连接方式（用时最长的：LAN、P2P、TURN 及其 UDP / TCP / TLS、SFU）、分辨率、平均帧率、平均延迟、卡顿次数（画面停住 0.3 秒以上而视频仍在到达）、重连次数 | 主控在窗口关闭或切换设备时上报 |
| 是否用过键鼠控制；文件传输（方向、文件或文件夹名、大小、完成 / 取消 / 失败 / 中断）；端口转发的目标 | 被控在参与者离开时上报 |
| 不经服务器的连接（局域网直连、仅直连）：双方、关系、时间与上面两方的摘要 | 双方各自上报（需已登录） |

访问码输错不会出现在记录里：访问码在主控本机核对（SPAKE2），输错时什么也不发给服务器和被控。

## 二、账号记录

| 事件 | 谁看得到 |
| --- | --- |
| 登录（含失败）、二次验证、邀请码注册、退出登录、移除某台设备的登录、修改密码、开关二次验证 | 本账号 |
| 管理员修改账号、重置密码或二次验证、解绑设备、强制下线 | 被操作的账号 |
| 重命名、移除设备 | 本账号 |
| 远程关机、重启、唤醒 | 发起的账号与设备的主人 |
| 添加、删除好友，修改给好友的权限 | 双方 |
| 开关访问码，信任设备、取消信任 | 本账号（由被控设备上报） |

## 三、不记录

画面、声音、键盘与鼠标输入、剪贴板（内容与次数）、文件内容、每一次网络切换与重连（只计次数）、画质与分辨率切换、显示器切换、麦克风、批注、设备上下线。

## 四、谁能看到连接记录

- 连接双方的账号：被控设备的主人看到谁连了它（含来源 IP 与做了什么），主控的账号看到自己连了哪里。好友只看到自己作为主控的那些。
- 没有账号的访客：服务端的记录归被控一方；访客本人看不到。
- 管理员：全部。

## 五、实现

- 主控为每个观看窗口生成一个 visit ID，创建会话（`POST /sessions`、访客的 `accept`）时带上；服务器按（主控设备、被控设备、visit）把会话归入同一条记录，上一个会话结束 6 分钟内同一 visit 的新会话重新打开这条记录（重连），否则开始新的一条。直连时 visit 放在 `session.start` 里交给被控。
- 被控从 `session.incoming` 得知 visit，在参与者离开时把摘要放进待发队列，由被控进程（装了后台服务时是服务）的账号上传（`POST /records/reports`）；服务器暂时连不上时每分钟重试，最多保留 200 条（进程退出时丢失）。访问码与受信任设备的变化同样经这个队列上报（`POST /devices/self/events`）。
- 主控的摘要在窗口关闭（或切换到另一台设备）时由窗口所用的账号上传，访客用其游客身份。
- 不经服务器的连接：第一份上报建立记录；记录只归入上报方的账号，另一方也上报后才归入另一方的账号（防止伪造的记录出现在别人的列表里）。
- 接口：`GET /records?device=&before=`、`GET /me/events?before=`、`GET /admin/records?user=&device=&before=`，见 [protocol/farwing-protocol.md](protocol/farwing-protocol.md)。

## 对方能看到什么

- 未获放行的尝试（访问码错误、被拒绝、无人应答、人数已满）：访客自己的记录里没有被控的设备 ID、名称与账号，只显示时间与结果。
- 放行后的连接：双方能看到对方的设备名称与 ID，看不到对方的账号 ID。
- “账号”事件中的 IP 只显示本账号自己操作时的地址（以及针对本账号的登录失败），不显示好友或管理员操作时的地址；同名的新账号看不到旧账号的事件。
