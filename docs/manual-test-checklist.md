# Farwing 0.1.0 双机手动测试清单

本清单覆盖本机无法验证、或只在本机回环上验证过的功能。每项给出前置条件、步骤与预期结果；记录结果时请附上两端日志（`%LOCALAPPDATA%\Farwing\logs`，多 profile 时在 `profiles\<名称>\logs`；安装后台服务后，服务的日志在 `C:\Windows\System32\config\systemprofile\AppData\Local\Farwing\logs`）与诊断包。

单机多 profile 已验证的项目与结果见 [selftest-results.md](selftest-results.md)；剩余项目按环境分批的执行顺序见 [dual-machine-runsheet.md](dual-machine-runsheet.md)。

需要更详细的日志时，可在任意命令前加 `--log-level "info,farwing::transport=debug"` 之类的过滤串（语法同 `RUST_LOG`）。

## 0. 环境准备

| 编号 | 内容 |
| --- | --- |
| 0.1 | 两台 Windows 10/11 x64：**H**（被控）与 **C**（主控）。建议至少一台带独立显卡（NVIDIA/AMD/Intel 任一），另一台可为核显。 |
| 0.2 | 一台 Farwing Server（公网或局域网均可），版本与客户端同一构建。服务端配置至少一个 `[[turn.stun]]`；做 NAT 探测测试时配置两个公网 IP 或至少两个端口。 |
| 0.3 | 账号：`alice`（H 与 C 都登录）、`bob`（第三台机器或 C 的另一个 profile，用于好友测试）。 |
| 0.4 | 网络：同一局域网；另准备一个不同网络（手机热点）用于公网 / NAT 测试。 |
| 0.5 | 记录两端 `Farwing.exe` 版本（设置 → 关于）与服务端版本，确认均为 0.1.0 同一构建。 |
| 0.6 | 端口映射测试前确认你有路由器的管理权限，并同意让 Farwing 在路由器上创建 UPnP / NAT-PMP / PCP 映射。 |

## 1. 账号、设备与身份

设备 ID 由设备密钥推导，在任何服务器、局域网与直连中相同（`access-model.md` §2.1）。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| 1.1 | H、C 分别首次登录（自签证书时核对服务器证书指纹） | 设备中心“设备 → 我的设备”出现对方；`Farwing devices` 列出两台；每台的设备 ID 与它本机 `Farwing id` 显示的相同 |
| 1.2 | 用其他结构版本的 `farwing.db`（如 0.1.0 之前的测试版本留下的）启动服务端 | 拒绝启动并提示 `no migration: move the file aside to start with an empty database`（不兼容旧版本，没有迁移）；把文件移走后启动得到空数据库，重新创建账号、客户端重新登录 |
| 1.3 | 在 H 上删除 Farwing 凭据（产生新设备密钥）后重新登录，C 刷新设备列表并连接 | H 以一台新设备（新的设备 ID）出现，旧的 H 显示离线，可在其详情中移除；C 直接连接新设备，没有“身份变化”之类的提示 |
| 1.4 | `Farwing sessions` 列出登录设备；对另一台执行 `--revoke` | 被撤销的设备立即掉线并需要重新登录 |
| 1.5 | 断网 30 s 后恢复 | 在线状态自动恢复，无需重新登录 |
| 1.6 | 服务器域名同时解析出 IPv6 与 IPv4，但只有其中一个可达（或用 `localhost` 指向只监听 IPv4 的服务端） | 登录与连接不因不可达的地址额外等待（每次连接不应多出约 2 s） |
| 1.7 | 全新安装（或新 profile）启动 | 先显示“连接服务器”：填写地址点“下一步”，证书受信任或指纹一致时进入“登录账号”；不受信任时显示服务器证书指纹，确认后继续；也可以选“不使用服务器 · 局域网直连” |
| 1.8 | 登录后在“设置 → 账号与服务器”点“更换服务器…”并确认 | 退出账号，回到“连接服务器”（地址与指纹已预先填好）；改为其他服务器后登录：设备 ID 不变（与服务器无关）；改回原服务器再登录同样不变 |
| 1.9 | 打开本账号设备的详情；更新到本版本后各设备重启一次 | 硬件信息中的“内存”显示实际大小（如 31.4 GB）；设备卡片与详情页的壁纸上没有 Farwing 图标；详情只有“设备 ID”一行，没有单独的“设备指纹” |
| 1.10 | 新 profile 在登录页选“不使用服务器 · 局域网直连” | 进入“设备”页“附近”标签；“我的设备”“好友共享”标签与侧边栏“好友”带锁说明（“设置服务器并登录 / 附近的设备”）；“本机”页顶部提示没有服务器、只能直连，短号显示“没有服务器时没有短号”；左下角“未登录 · 未设置服务器” |
| 1.11 | 设置服务器后在第二步选“无需登录 · 让别人连接本机” | 进入“本机”页：开启访问码后显示短号与访问码；左下角显示服务器地址；设置 → 账号与服务器显示“未登录”“更换服务器…”与本机 ID |
| 1.12 | 侧边栏 | 只有“设备 / 好友 / 本机 / 设置”；“本机”有人连接时显示人数 |
| 1.13 | “设备”页连接栏依次输入：本账号设备的 ID、好友共享设备的 ID、附近设备的 ID、其他设备的 ID、9 位短号、`192.168.x.x` | 输入框下方依次提示：经账号连接 / 经账号连接 / 在局域网中，直连 / 经服务器请求连接（对方信任本机时无需访问码）/ 短号经服务器 / 地址直连；无法识别的输入提示格式 |
| 1.14 | “设备”页四个标签 | 我的设备（卡片、搜索筛选与原来相同）、好友共享（按好友分组，局域网中的标“可直连”）、附近（本账号 / 某某共享 / 对方信任本机 / 需要访问码，对应“连接”或“输入访问码”“请对方确认”）、最近与收藏（收藏的短号 + 连接过的设备，同一台设备只出现一次） |
| 1.15 | “附近”中对一台需要访问码的设备点“输入访问码” | 地址填入连接栏、焦点在访问码框，提示“请输入 … 的访问码” |
| 1.16 | “本机”页 | 依次为：本机（设备 ID、短号、局域网地址可点击复制，“允许连接本机”开关）、访问码、受信任设备、本账号的设备与好友、正在连接、上限 |
| 1.17 | “本机”页关闭“允许连接本机” | 状态点变灰并说明关闭后任何设备都不能连接；开启访问码时若总开关关闭，会自动打开 |
| 1.18 | 访问码卡片：切换类型（临时 / 固定 / 都接受）、方式（访问码 / 访问码 + 本机确认 / 仅本机确认），换一个临时访问码，“复制邀请” | 卡片说明随之变化；邀请文字含设备 ID、短号与访问码（固定访问码时不含，提示单独获取） |
| 1.19 | 访客连接后，在“本机 → 正在连接”中点“信任” | 提示已信任；“受信任设备”出现该设备，权限为当前访客权限；“权限”可修改，“移除”需确认并断开它的连接 |
| 1.20 | 全程查看文案 | 不再出现“配对码”“协助验证码”“设备号”“设备指纹”；只用设备 ID、短号、访问码（临时 / 固定）、受信任设备、访客、本机确认 |

## 2. 好友与授权

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| 2.1 | bob 申请加 alice 为好友，alice 接受 | 双方好友列表出现对方；bob 的“好友”页 alice 名下与“设备 → 好友共享”中出现 H，“可以：观看画面、批注”，并显示 H 的设备 ID；bob 的“我的设备”中没有 H |
| 2.2 | bob 连接 H | 只能观看与批注；键鼠、剪贴板、文件、端口不可用（菜单置灰或提示无权限） |
| 2.3 | 会话进行中，alice 在“好友”页为 bob 对 H 增加“键鼠控制” | 无需重连，bob 立即可以控制 |
| 2.4 | 会话进行中撤销“键鼠控制” | bob 立即只能观看；H 上 bob 按住的键被释放 |
| 2.5 | alice 解除好友 | bob 的会话立即结束，H 从 bob 的列表消失 |
| 2.6 | alice 在“好友”页对 bob 点“设置权限”：默认选“仅观看”，把 H 设为“不共享”，保存 | 对话框关闭并提示已保存；bob 的“好友共享”中 H 消失，其他设备只能观看。改回后恢复 |
| 2.7 | “我的设备”底部展开“本机与其他登录设备”，进入一台旧登录设备的详情并移除 | 该设备从账号移除，它上面的登录失效 |
| 2.8 | alice 对 bob 选“默认都不共享”，只把 H 设为“单独设置”，保存 | bob 的“好友”页与“好友共享”中只剩 H，其余设备完全看不到；用设备 ID 直接连接其他设备时按陌生设备处理（需要访问码） |
| 2.9 | 对照设备 ID：H 的“设备详情”、C 的“我的设备”、观看窗口“切换设备”菜单、“附近”、“最近与收藏”，以及 H 上“正在连接”中 C 的 ID | 同一台设备在各处的设备 ID 相同 |
| 2.10 | bob 与 H 在同一局域网：bob 在“附近”中点 H 的“连接”，或 `connect --direct <H 地址>` | H 按好友权限直连接纳（H 日志 `relation=Friend`，单机已验证）；alice 撤销 bob 对 H 的授权后再连，立即被拒绝（单机已验证） |
| 2.11 | 停止服务端后 bob 直连 H | 按 H 缓存的好友授权接纳（缓存 7 天）；服务端恢复后授权变化立即生效 |

## 3. 经服务器连接：访问码与受信任设备

“访客”用访问码或本机确认连接一次；“受信任设备”由被控记住，以后无需访问码（`access-model.md` §2.2–2.4）。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| 3.1 | H 开启访问码（临时访问码），C 用 bob 账号在连接栏输入 H 的短号与正确访问码 | 连接成功，权限为“访客可以” |
| 3.2 | 输入错误访问码 | 提示“访问码不正确”；H 记录一次失败 |
| 3.3 | 1 分钟内错误 11 次 | H 在 5 分钟内拒绝并在界面提示“多次收到错误的访问码，访问码已暂停 5 分钟” |
| 3.4 | H 设为“仅本机确认” | C 无需访问码，H 弹出“连接请求”（显示 C 的名称与设备 ID，按钮“拒绝 / 允许并信任 / 允许本次”）；拒绝后 C 收到拒绝 |
| 3.5 | H 选“两种都接受”（临时与固定访问码），分别用两者连接 | 两者都能通过 |
| 3.6 | H 已有 alice 的会话时 bob 以访客连接 | bob 加入，alice 不被顶替 |
| 3.7 | 未登录的 H（登录页第二步“让别人连接本机”）开启访问码 | 未登录的 C 用短号或 H 的设备 ID 加访问码即可连接（单机 CLI 已验证） |
| 3.8 | C 未登录（只设置了服务器），在连接栏输入 H 的设备 ID 并连接 | H 要求访问码时弹出“输入访问码”；输入后连接成功（访客） |
| 3.9 | 3.4 中 H 选“允许并信任” | 本次连接成功；H 的“受信任设备”出现 C；C 断开后再次用 H 的设备 ID 或短号连接，无需访问码和确认（H 日志 `relation=Trusted`，单机已验证） |
| 3.10 | H 关闭访问码，只保留受信任设备 | 受信任的 C 仍能经服务器连接；其他设备被拒绝（“对方没有开启访问码，也没有信任这台设备”） |
| 3.11 | H 在“受信任设备”中把 C 的权限改为只“观看”，C 重连 | C 只能观看；H 移除 C 时 C 的会话立即结束，再连需要访问码 |
| 3.12 | 最近与收藏：把 3.1 的短号加入收藏并保存访问码 | 收藏中出现该设备（短号与设备 ID）；点“连接”直接使用保存的访问码 |

## 5. 弱网策略与观影模式（需要可控的弱网）

用路由器 QoS 或在中间加一台限速设备，把 H→C 方向限速到 3 Mbps，再恢复。

| 编号 | 步骤 | 预期 |
| --- | --- | --- |
| 5.1 | “网络不佳时 = 优先降低码率”，1080p 60 fps，限速 | 分辨率不变；码率先降，降到档位上限 1/4 后才降帧率，最低 30 fps |
| 5.2 | 同上，改为“优先降低帧率” | 帧率先降（最低 30），每帧质量基本保持 |
| 5.3 | 解除限速 | 帧率每 3 s 最多回升 10 fps，最终恢复设定值 |
| 5.4 | 开启“观影模式”播放视频 | 播放平稳、音画同步；延迟比关闭时略高（HUD 的“帧延迟”约 +120 ms），但不变红、不出现延迟告警图标；统计面板“估算帧延迟”注明“含观影缓冲” |
| 5.5 | 制造 2% 丢包（如可用） | 画面无长时间卡住；丢包后很快恢复（快速关键帧） |

## 6. 连接恢复与被控生命周期

| 编号 | 步骤 | 预期 |

| 6.1 | 观看中，C 从 Wi-Fi 切到有线（或反之） | 2–4 s 内恢复画面，不重建会话（C 日志 `local network path changed` 与 `ICE restarted`） |

| 6.9 | H 的网卡 / VPN / 虚拟网卡频繁变化但默认路由不变（如开关 VMware 网卡） | 不触发 ICE 重启，画面不中断 |

| 6.16 | 观看中让 C 睡眠约 1 分钟后唤醒 | 唤醒后自动恢复画面（C 日志 `system resumed; checking the connection`） |
| 6.14 | C 已安装服务（界面进程没有自己的在线连接）时打开 H | 自动使用单独实时连接（`via_presence=false`），功能正常 |
