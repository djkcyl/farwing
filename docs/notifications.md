# 通知

账号在网页端和客户端都能收到通知：网页端侧栏“通知”带未读数，客户端侧栏“通知”带未读数，新的通知按本机的“通知方式”（窗口内卡片或 Windows 通知）弹出。没有外部渠道（邮件、Webhook）。

## 一、通知的种类

| 种类 | 默认 | 收到的人 | 设备上 |
| --- | --- | --- | --- |
| 新设备登录（以前没登录过本账号的设备；账号的第一台设备不算） | 开 | 本账号 | 除登录的那台 |
| 登录连续失败（10 分钟内 5 次，到第 5 次时通知一次） | 开 | 本账号 | 全部 |
| 密码与二次验证变更（含管理员重置） | 开 | 本账号 | 除操作的那台 |
| 设备被移除、退出登录，管理员解绑或强制下线 | 开 | 本账号 | 除操作的那台和被移除的那台 |
| 他人连接我的设备（好友、访客、受信任设备；重连不算新连接） | 开 | 被控设备的主人 | 除被控本身（它已有本机通知） |
| 连接未成功（对方拒绝、无人确认、人数已满） | 开 | 被控设备的主人 | 除被控本身 |
| 好友远程开关机（关机、重启、唤醒） | 开 | 设备的主人 | 除该设备 |
| 好友申请、好友申请通过、好友修改了给你的权限 | 开 | 对方 | 全部 |
| 本账号设备之间的连接 | 关 | 本账号 | 除主控与被控 |
| 设备离线 10 分钟（服务器启动后在线过的设备） | 关 | 设备的主人 | 除该设备 |
| 访问码开关、受信任设备增删 | 关 | 本账号 | 除该设备 |
| 证书自动申请失败（每轮失败通知一次） | 开 | 管理员 | 全部 |
| 中转节点离线 5 分钟 | 开 | 管理员 | 全部 |
| 有人用邀请码注册了账号 | 开 | 管理员 | 全部 |

每个账号在网页端“账号与安全 → 通知”或客户端“通知”页下方逐项开关；只保存与默认不同的选择。

## 二、实现

- 服务器在上述事件发生时为相关账号各写一条通知（`notices` 表，保留期与审计日志相同），并向该账号在线的设备推送 `notice`。
- 网页端每 30 秒（以及页面回到前台时）读一次未读数；打开“通知”页即全部标为已读。
- 客户端：被控进程（装了后台服务时是服务，经快照转给界面）收到 `notice` 推送时只记下“有新通知”；设备中心随后（以及每分钟一次）读最新 20 条，比上次已知的更新的弹出卡片。启动时已有的通知不弹出，只计入未读数。打开“通知”页即全部标为已读。
- 接口：`GET /me/notices?before=&limit=`（`limit=0` 只取未读数）、`POST /me/notices/read`、`GET`/`PUT /me/notice-settings`，见 [protocol/farwing-protocol.md](protocol/farwing-protocol.md)。
