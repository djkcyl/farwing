# 服务端管理、中继节点与多人转发设计（草案，2026-10-23）

本文档记录服务端下一轮改造的设计：网页化管理、配置热重载、单机与分布式部署、多人转发（SFU）。已确定的决定见 §0；其余为建议，实施前与用户核对。

## 0. 已确定的决定

| 事项 | 决定 |
| --- | --- |
| 命令行 | 只保留启动与一个应急命令，其余全部改为网页与 HTTP 接口 |
| 配置生效 | 按组件热重载，不重启进程 |
| 分布式选节点 | 客户端测量到各节点的延迟，服务端为会话两端各选最近的节点 |
| 多人转发 | 提供端到端加密与兼容两种模式，在安全与兼容性之间取舍 |

部署形态：

- **单机**：一个 `farwing-server` 进程包含账号、信令、网页、STUN、TURN（UDP / TCP / TLS）、NAT 探测，安装后默认全部开启，不依赖任何外部服务。
- **分布式**：一个控制节点 + 任意多个边缘节点（同一个程序）。边缘节点提供 STUN、TURN、NAT 探测，之后兼任多人转发（SFU）；客户端用哪个节点由控制节点决定。

## 1. 现状（2026-10-23）

- 配置来自 TOML 文件（`listen`、`public_url`、`data_dir`、`[tls]`、`[guest]`、`[web]`、`[turn]`、`[[turn.stun]]`、`[limits]`）；网页端只能改 5 项（实例名、游客、邀请码注册、码率上限、网页端功能），其余只读，修改需编辑文件并重启。
- 命令行：`init`、`serve`、`user create/list/promote/demote/reset-totp/passwd/disable/enable/delete`、`device list/remove`、`session list`、`friend list`。
- 网页与客户端的接口都用设备签名请求（`FWREQ2`，Ed25519），curl 无法直接调用。
- 中继：`[turn] mode = "builtin" | "external" | "none"`。`init` 生成的配置默认 `external`（需要另装 coturn），README 也推荐 coturn；内置模式只有 UDP / TCP，没有 TLS；中继端口不设范围时随机。
- 每个会话的两端拿到同一份 ICE 服务器列表（服务端自己的 STUN / TURN），没有按地域选择；NAT 探测只有本机的端口。
- 服务端不知道哪些会话经过中继，也不限制中继带宽。
- 多人：被控与每位参与者各一条 WebRTC 连接；同一屏幕同一参数只编码一次（每个被控最多 4 路），编码后的包分别发给每个人，被控上行 = 各人码率之和；媒体全程端到端加密（DTLS 指纹由设备密钥签名），服务端与中继看不到内容。

## 2. 管理：网页与 HTTP 接口

### 2.1 命令行

```
farwing-server [--data-dir <目录>] [--listen <地址:端口>]   运行（默认数据目录为程序旁的 data，默认监听 0.0.0.0:8443）
farwing-server setup-code [--data-dir <目录>]              生成一次性初始化码（应急：所有管理员都无法登录时）
farwing-server edge --join <加入链接>                      以边缘节点运行（§4）
```

- 删除 `init`、`user`、`device`、`session`、`friend` 与 `--config`。不迁移旧配置文件与旧数据库（发布前不做兼容）。
- 环境变量 `FARWING_DATA_DIR`、`FARWING_LISTEN` 与参数等价（Docker、systemd 使用）。

### 2.2 初始化

- 数据库里没有管理员时进入“未初始化”状态：控制台与日志打印一次性初始化码和初始化网址（`https://<任一本机地址>:8443/setup`），初始化码 24 小时有效，用过即失效；`setup-code` 命令可以重新生成（同时作废旧码）。
- 未初始化时，除 `/setup` 与它的接口外，其余接口返回 `setup_required`；客户端提示“服务器尚未初始化”。
- 初始化向导（每步可返回修改，最后一次性提交）：
  1. 输入初始化码。
  2. 对外地址：客户端连接用的域名或 IP 与端口（预填浏览器访问用的地址）。
  3. 证书：自签名（默认，显示指纹）/ 自动申请（ACME，需域名与 80 或 443 可达）/ 上传证书与私钥。
  4. 中继与探测：内置中继默认开启；公网 IPv4（预填：访问地址是 IP 时用它，否则解析域名），端口 3478（UDP / TCP）、TLS 中继 5349、NAT 探测 3479–3480、中继端口 49160–49200；向导列出需要放行的端口。
  5. 管理员账号与密码（可选同时开启二次验证）。
  6. 游客与注册策略。
- 初始化完成后进入正常状态，网页跳转到管理后台的“服务器概览”。

### 2.3 设置存储

- 所有设置存在数据库（`settings` 表，键值 + 版本号），没有配置文件；启动参数只有数据目录与监听地址（首次启动后监听地址也存入数据库，以数据库为准，参数只在数据库没有时使用）。
- 网页“服务器设置”按组分页：基本（实例名、对外地址）、证书、中继与探测、节点（§4）、多人转发（§5）、游客与注册、网页端、限额与超时、日志。
- 每次保存写入审计日志（改了哪些键，密钥类只记“已修改”）；可导出、导入设置（JSON，密钥类可选择是否包含）。
- 密钥（TURN 主密钥、节点派生密钥、ACME 账号）存在数据目录，不进导出（除非显式选择）。

### 2.4 HTTP 接口与管理令牌

- 管理员可在网页生成**管理令牌**：名称、有效期（30 天 / 90 天 / 1 年 / 永久）、权限（只读 / 管理）、可选来源地址限制；令牌只显示一次，只存哈希，可吊销，每次使用记录最后使用时间与来源。
- 用法：`curl -H "Authorization: Bearer fwa_…" https://<服务器>/api/v2/admin/...`。管理令牌只能调用管理接口，不能登录客户端或网页。
- 网页上的每个管理功能都有对应接口（账号、邀请码、设备、会话、更新公告、设置、节点、审计日志、令牌本身）；`docs/server-admin-api.md` 列出全部接口与 curl 示例。
- 原命令行的功能对应：`user *` → `/admin/users`；`device list/remove` → `/admin/devices`；`session list` → `/admin/sessions`；`friend list` → `/admin/users/{id}/friends`；`init` → 初始化向导与 `/setup` 接口。

## 3. 改设置后的生效方式（热重载）

设置保存后，服务端按变化的组件分别重载，进程不重启。

| 组件 | 设置 | 生效方式 | 对在线用户的影响 |
| --- | --- | --- | --- |
| 业务设置 | 实例名、游客、注册、码率上限、网页端功能、限额、超时、审计保留、管理来源限制、日志级别 | 立即替换内存中的值 | 无 |
| 中继凭据 | 凭据有效期、强制中继、主密钥轮换 | 新会话用新值；轮换主密钥时旧密钥再保留一个有效期，已签发的凭据继续有效 | 无 |
| 证书 | 上传新证书、切换自签名 / ACME | 证书解析器热替换（ACME 续期已经是这样） | 无；客户端若固定了旧指纹会提示核对新指纹 |
| HTTPS 监听 | 地址、端口 | 先在新端口开始监听；网页跳转到新地址后 60 秒内点“确认”才关闭旧端口，不确认自动撤销 | 在线连接继续使用旧端口直到确认；确认后客户端按新地址重连 |
| 对外地址 | 域名、端口 | 立即用于新签发的地址；同时推送给在线客户端 | 客户端更新保存的服务器地址 |
| 内置中继 | 端口、公网 IP、中继端口范围、开关 | 只重启中继组件 | 正在走本机中继的连接断开几秒后由客户端的通道重建恢复；保存前显示受影响的中继分配数 |
| NAT 探测 | 端口 | 只重启探测组件 | 无（客户端下次探测时使用） |
| 数据目录 | — | 不能在线修改 | — |

实现要点：服务端组件（HTTPS、中继、探测、ACME、边缘节点管理）各自持有一份当前设置的快照，订阅设置变化；变化时组件比较新旧值，自行替换或重启。设置校验在保存前完成（端口冲突、地址格式、证书与私钥匹配），校验失败不保存。

## 4. 中继、探测与分布式节点

### 4.1 单机默认

- 内置中继默认开启：STUN / TURN UDP 3478、TURN TCP 3478、**TURN TLS 5349**（端口可自定义；复用 HTTPS 的证书）、中继端口 49160–49200、NAT 探测 3479–3480。
- `external` 模式（coturn）保留为可选：已有 coturn 的部署填写地址与共享密钥；`none` 删除（只要不想提供中继，关闭内置中继即可）。
- 客户端拿到的 ICE 服务器：STUN（含探测端口）、TURN UDP / TCP / TLS。观看窗口的“使用中转”在服务器提供任一种中转时可用。
- 自签名证书时：原生客户端按服务器指纹校验 TURN TLS（与 HTTPS 相同）；浏览器不接受自签名的 TURN TLS，网页端只能用 UDP / TCP 中继。用 ACME 证书时两者都可以。

### 4.1a 线路类别与中转方式的选择

- 中转的“UDP / TCP / TLS”指客户端与中转服务器之间那一段的协议；中转服务器到对端一段、媒体的端到端加密都相同。TCP / TLS 只在这一段丢包时才因重传造成卡顿；国内运营商限速主要针对 UDP，走 443 的 TLS 很少被限，所以 UDP 被 QoS 时 TLS 中转可能更稳，而信号差的 Wi-Fi、移动网络或很远的中转节点上 UDP 中转（配合 FEC 与重传）恢复得更快。
- 因此不固定优先级：客户端把可用路线分为三类——直连、UDP 中转、TCP / TLS 中转——按 v2-design §11 的实测代价比较；不在用的类别都定时探测，切换到任何一类之前都先压测（取代现在只比较“直连 / 中转”两类的做法）。
- 观看窗口的手动开关改名为“使用中转”：在 UDP 与 TLS 中转中选实测代价最低的；还没有测量时先用 TLS 中转；服务器没有 TLS 中转时用 UDP / TCP 中转。界面统一叫“中转”。

### 4.2 节点角色

| 角色 | 提供 | 数量 |
| --- | --- | --- |
| 控制节点 | 账号、信令、网页、数据库、节点管理与调度；同时可以是一个中继节点 | 1 |
| 边缘节点 | STUN、TURN（UDP / TCP / TLS）、NAT 探测；之后提供多人转发（§5） | 0–N |

边缘节点没有数据库与账号，只保存加入时得到的身份与证书；所有配置由控制节点下发。

### 4.3 加入与通信

1. 管理员在网页“节点”页点“添加节点”，填写名称与可选的地区标签，得到一条加入命令：`farwing-server edge --join https://<控制节点>/join/<一次性令牌>#<控制节点证书指纹>`（令牌 1 小时有效）。
2. 边缘节点生成自己的 Ed25519 密钥，用令牌向控制节点登记（校验证书指纹），得到节点 ID；之后与控制节点保持一条 WSS 长连接（节点签名请求，与设备相同的机制），断开后自动重连。
3. 控制节点通过这条连接下发配置（端口、公网 IP、中继范围、证书、凭据派生密钥）并接收上报：每 10 秒的健康状态、当前中继分配数、各分配的会话 ID、收发带宽、CPU 与内存；节点自检公网可达性（由控制节点向它的 STUN 端口发探测）。
4. 节点可在网页上停用（不再分配新会话，现有分配保留到结束）、摘除（吊销身份）、编辑名称与地区标签、设置带宽上限。

### 4.4 凭据

- 每个节点一个派生密钥 `K_node = HKDF(主密钥, 节点 ID)`，由控制节点下发；TURN REST 凭据用节点的密钥签名，边缘节点本地校验，不用每次询问控制节点。
- 凭据用户名加入节点 ID：`<过期>:<会话 ID>:<节点 ID>`，节点只接受签给自己的凭据。
- 摘除节点时轮换该节点的派生密钥；主密钥轮换时所有节点的派生密钥随之更新，旧密钥保留一个凭据有效期。

### 4.5 选节点（客户端测速）

- 客户端在在线连接建立时、网络变化后（2 秒去抖）与每 30 分钟，向控制节点下发的“测速列表”中每个节点的 STUN 端口发 3 次 Binding 请求（并行，最多 2 秒），取最小 RTT，经在线连接上报 `{node_id: rtt_ms | null}`；同一轮测速同时完成 NAT 探测（§4.6）。
- 控制节点为每台在线设备保存最近一次测量；创建会话时为两端各选 2 个节点：按 RTT 排序，跳过停用、不健康或带宽已满的节点，地区标签只在没有测量时作为参考。
- 会话的 ICE 服务器列表按端下发：被控拿到它的 2 个节点，主控拿到它的 2 个节点。两端各在离自己近的节点上分配中继；需要中继时，媒体走“主控 → 主控的节点 → 被控的节点 → 被控”，路径由客户端现有的线路选择（实测代价）决定。
- 控制节点自身也是一个节点（可在设置中关闭它的中继），没有任何边缘节点时即为单机部署。

### 4.6 NAT 探测

- 每个节点开两个探测端口；客户端把多个节点（不同 IP）当作 RFC 5780 的“另一地址”：映射行为的测试（向不同 IP、不同端口发请求比较映射）只需要多个节点，可以完整判断；过滤行为的测试（请服务端从另一端口 / 另一 IP 回复）在单个节点内用两个端口完成。
- 只有一个节点时与现在相同（只能判断换端口的情况）。

### 4.7 统计

- 由节点上报的分配与会话 ID，概览页显示“经中继的会话”与各节点的带宽；会话页标注每个会话是否经中继、经哪些节点。
- 每个节点可设带宽上限；超出时不再为新会话分配该节点。按账号的中继流量限额作为后续项。

## 5. 多人转发（SFU）

### 5.1 何时使用

- 参与者 1–2 人：保持现在的直连方式（延迟最低）。
- 参与者达到阈值（默认 3 人，可设置）或被控上行不足（发送端的带宽估计低于各人码率之和）时，被控改为把每路编码上传一份到 SFU，由 SFU 分发给该路的成员；人数回落后切回直连。
- SFU 运行在边缘节点上（单机时在控制节点上），按被控的测速结果选最近的节点。

### 5.2 连接方式

- 媒体：被控 → SFU 一条连接（每路编码一个视频轨，共享的系统声音一个音频轨）；SFU → 每位参与者一条连接。
- 其余通道（键鼠、剪贴板、文件、光标、控制权、显示设置）仍走被控与每位参与者之间的连接（直连或经中继），带宽很小；切换到 SFU 时只把媒体轨移走。
- 关键帧与丢包：SFU 缓存最近的包，直接回应各参与者的重传请求；参与者的关键帧请求在 SFU 合并后转给被控（每路每 RTT 最多一次）。
- 每人带宽不同：第一版沿用现在的“整路跟随最弱成员”；之后用分层编码（时间分层）让 SFU 为网速差的成员丢掉部分层。

### 5.3 两种模式

| | 端到端加密模式（默认） | 兼容模式 |
| --- | --- | --- |
| 服务器能否看到画面 | 不能：被控在编码后、分包前对每帧加密，SFU 只转发密文 | 能：SFU 解开传输加密后转发 |
| 密钥 | 每路编码一个帧密钥，被控经与每位参与者之间已认证的连接分发；成员变化时更换 | 不需要帧密钥 |
| 原生客户端 | 支持 | 支持 |
| 网页端 | 需要浏览器支持编码帧变换（WebRTC Encoded Transform）；不支持的浏览器在这种模式下不能经 SFU 观看，退回直连 | 所有支持的浏览器 |
| 被控身份校验 | 参与者照常校验被控的签名（密钥经已认证的连接下发） | 参与者对媒体连接改为校验 SFU 节点的证书（由控制节点签发），并显示“画面经服务器转发” |

- **选择**：服务器管理员在“多人转发”设置中决定是否启用 SFU、是否允许兼容模式；被控设备的主人在本机设置中选择自己的屏幕使用哪种模式（默认端到端加密），主控在参与者面板看到当前模式。
- 帧加密的格式、各浏览器对编码帧变换的实际支持，在实施前单独做一次验证。

## 6. 实施阶段与验收

| 阶段 | 内容 | 本机可验收 | 需要实测 |
| --- | --- | --- | --- |
| A | 命令行精简、初始化向导、设置入库、管理令牌与接口、按组件热重载 | 全部（初始化、各组件重载、令牌调用、审计） | — |
| B | 内置中继默认开启、TURN TLS、去掉 `none`、端口默认值；线路分三类按实测选择（§4.1a）；“使用中转”开关 | TLS 中继在本机经 TURN 连接；三类线路间的切换与压测（模拟丢包） | 公司网络（只放行 443）下的中继；运营商 UDP 限速时 TLS 中转的效果 |

每个阶段完成后更新本文档的状态、`farwing-protocol.md` 的接口与消息、服务端 README 与测试包。

## 7. 实施状态

### 阶段 A（2026-10-23，已完成）

已实现：命令行只剩启动（`--data-dir`、`--listen`，及对应环境变量）与 `setup-code`；未初始化时只有 `/setup` 应答；设置是数据库中的一份 JSON 文档；网页端“服务器设置”六组与“API 令牌”页；按组件生效（§3）；接口与 curl 示例见 [server-admin-api.md](../server-admin-api.md)。本机验证：服务端集成测试（初始化与错误码、恢复管理员、令牌的权限 / 网络 / 吊销、内置中继随设置启停与端口占用被拒、监听地址确认与撤销、证书上传、导出导入），网页端在本机 Chrome 中走完初始化、各组设置、令牌创建与 curl 调用、监听地址确认条的撤销与 60 秒自动恢复。

与上文设计不同之处：

- 初始化向导是一页表单（初始化码、管理员、实例名与对外地址、证书、中转、注册与游客），不在向导中设置监听地址与二次验证；向导中改为反向代理模式时直接生效，不需要确认。
- `--listen` 指定时总是覆盖数据库中的值，且网页上不能修改（容器使用）；不指定时以数据库为准。
- 中转共享密钥保存在设置文档中（数据库），读取与默认导出时隐藏；更换密钥立即生效并重启内置中转，旧凭据不再保留一个有效期（经中转的连接自动重连）。
- 审计日志记录改动的设置组（`{"groups": [...]}`），不逐键记录。
- 监听地址的确认可以从新地址或旧地址发出；同一地址上切换反向代理模式时旧监听立即关闭，只能从新地址确认。
- 尚未实现：对外地址变化时推送给在线客户端；保存中转设置前显示受影响的中继分配数；`/admin/users/{id}/friends`（好友与授权仍在账号详情中）。

### 阶段 B（2026-10-23，已完成）

已实现：内置中转默认开启并提供 TLS 中转（`turn.listen_tls`，默认 5349，可改；使用网页端证书，反向代理模式下不启动）；`turn.mode` 去掉 `none`，改为内置模式的“提供中转”开关（`turn.relay`，关闭时只运行 NAT 探测端点）；客户端把路径分为直连、UDP 中转、TCP / TLS 中转三类，按实测代价选择（farwing-protocol §7.6、v2-design §11）；观看窗口开关改名“使用中转”，使用服务器提供的全部中转方式，TLS 排在最前；界面统一叫“中转”。本机验证见 [selftest-results.md](../selftest-results.md) §53。

与上文设计不同之处：

- 中转类别按本端到中转服务器那一段的协议划分；只有对端是中转候选时按 UDP 中转计（对端那一段的协议无从得知）。
- Farwing 客户端连接 TLS 中转时不校验证书（中转凭据另有签名、媒体端到端加密），所以自签证书也可用；TLS 中转地址用公开地址的域名，公开地址是 IP 时用公网 IP。
- 新增：初始化与恢复管理员时可同时签发 API 令牌，完全不用浏览器也能部署与管理。

### 阶段 C（2026-10-23，已完成）

已实现：网页端“中转节点”页与 `/api/v2/admin/nodes`（添加并得到加入命令、编辑、停用、重新加入、移除）；`farwing-server edge`（加入、签名的长连接与自动重连、接收中转设置、每 10 秒报告健康与统计）；节点凭据按节点派生、只在该节点有效；设备在在线连接上测速并上报，会话两端各拿到最近的 2 个可用节点；节点的 STUN 端点并入 NAT 探测地址；概览与会话页的中转统计。本机验证见 [selftest-results.md](../selftest-results.md) §54。

与上文设计不同之处：

- 每个会话端拿到本服务器自己的中转（开启时）加上最近的 2 个边缘节点，而不是在包括本服务器在内的节点中选 2 个；不想让本服务器中转时关闭“提供中转”。
- 节点的 TLS 中转用节点自己生成的自签证书（客户端不校验中转证书），浏览器因此不使用节点的 TLS 中转；网页端只经 UDP / TCP 中转。
- 节点只在在线连接建立时得到测速列表（`hello`），节点增减后要等设备下次重连或 30 分钟后的重测；没有地区标签参与选择，没有测量时按名称排序。
- 节点的 CPU 与内存暂不上报；节点自检公网可达性（控制节点向它的 STUN 端口探测）未做。
- 本服务器的证书更换后（设置中），在线的节点随即收到新指纹；节点离线时证书更换（如自动申请的续期）则用系统信任校验，自签证书改名后需要重新加入。
