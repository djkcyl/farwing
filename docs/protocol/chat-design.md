# 聊天：群组、频道、私信、语音与屏幕共享（设计，2026-10-31）

在 Farwing 服务器上加一层类似 Discord / KOOK 的聊天：群组里的文字与语音频道、好友之间的私信与通话、摄像头与屏幕共享，以及从共享画面直接“请求控制”。远程桌面、好友授权与出口策略照旧，聊天建立在它们之上。

本文是实施前的设计，经逐项问答确定；各期完成后在 §15 记录状态与偏差。

## 0. 已确定的决定

| 事项 | 决定 |
| --- | --- |
| 群组 | 一台服务器多个群组；所有用户都能建（管理员可关），每人数量不限 |
| 私信 | 只在好友之间，只有一对一（没有小群私信） |
| 客户端 | 原生设备中心与网页同时完整实现；网页不能共享自己的屏幕，其余（语音、摄像头、观看、请求控制）都能 |
| 文字 | 回复与引用、编辑与撤回（不限时）、@提及、Markdown、置顶、全文搜索；不做表情回应、链接预览、自定义表情、话题串 |
| 状态 | 正在输入、账号在线状态（在线 / 离开 / 勿扰 / 隐身）、私信已读回执 |
| 表情 | Unicode emoji 加选择器，两端用 Fluent Emoji（MIT）图片 |
| 存储 | 服务端明文、永久保留；附件存服务端，单个 100 MB、每群组 10 GB（管理员可调） |
| 频道 | 文字、语音（自带文字区）、分类、公告 |
| 权限 | 自定义角色加频道按角色覆盖；不按单个成员覆盖 |
| 加入 | 邀请链接、拉好友、公开群组可搜索、可选加入需审批 |
| 管理 | 踢出与封禁、禁言与语音管控、慢速模式、群组审计日志；服务器管理员管理群组但不看内容；不做举报 |
| 语音 | Opus，按频道 32 / 64 / 96 / 128 kbps（默认 64）；转发每个人的声音；人数上限可设、默认不限；WebRTC 音频处理（回声消除、降噪、增益）加 AI 降噪一档；语音激活与全局按键说话 |
| 私信通话 | 点对点优先；所有设备响铃；每方一台设备 |
| 多设备 | 同一账号可用多台设备同时在语音频道里，声音照常转发 |
| 摄像头 | 720p30，大小两路，宫格 / 发言人布局 |
| 屏幕共享 | 整屏 + 系统声音、单窗口 + 该程序声音、只要画面；720p / 1080p × 30 / 60，随时切换；一个频道可多人同时共享 |
| 请求控制 | 共享者同意即为一次性授权，不要求开“允许被控” |
| 防回环 | 按进程排除 Farwing 的声音；老系统用已知参考信号抵消，抵消不掉就照常采集 |
| 加密 | 语音、摄像头、共享默认端到端，每人自己的帧密钥逐人加密分发；服务器“端到端加密”允许兼容时，群主可把语音频道设为兼容模式（项目范围的开关见 [camera-design.md](camera-design.md) §8） |
| 流量 | 经服务器转发的算接收者账号的，计入出口策略 |
| 顺序 | 一次完成，不分期：先做远程摄像头与媒体模块的复用改造，再依次做文字 → 语音与私信通话 → 摄像头、共享与请求控制，按阶段推进与提交（总顺序见 [camera-design.md](camera-design.md) §10） |
| 旧数据库 | 结构版本加一，不迁移 |

## 1. 范围

**做**：§0 所列。

**不做**（问答中确定不在范围内）：表情回应、链接预览、自定义表情、话题串、小群私信、举报、机器人与 Webhook、消息转发、服务端录制、游戏内悬浮窗、跨节点级联的语音频道、私信或群组文字的端到端加密、联邦（不同 Farwing 服务器之间互通）。

**规模**：自建的小团队与朋友圈子。单个群组几百名成员、几十个频道；一个语音频道几十人、同时几路共享。全部用 SQLite，不分库。

## 2. 概念与数据模型

### 2.1 概念

| 名称 | 说明 |
| --- | --- |
| 群组 | 有群主、成员、角色、分类与频道；可公开（可被搜索）或不公开 |
| 频道 | 属于群组，类型 `text`、`voice`、`category`、`announcement`；分类下可有频道（一层） |
| 私信 | 两个好友之间的会话；技术上是没有群组的 `dm` 频道 |
| 角色 | 群组内的权限集合；`@everyone` 是每个群组都有、不能删除的基础角色 |
| 成员 | 群组里的账号，可有群昵称、多个角色、禁言到期时间 |
| 消息 | 属于某个频道（含语音频道的文字区与私信） |
| 语音状态 | 某台设备在某个语音频道或私信通话里，及其静音、关闭声音、摄像头、共享状态（只在内存） |

### 2.2 标识

- 群组、频道、角色、消息、附件、邀请的 ID 都是 64 位整数（Snowflake：自 2026-01-01 起的毫秒数 << 22 | 节点内序号），按时间递增，JSON 中以十进制字符串传（避免 JavaScript 精度问题）。消息分页与“已读到哪里”都用 ID 比较。
- 账号与设备沿用现有 ID。

### 2.3 数据表（结构版本 8）

| 表 | 主要列 |
| --- | --- |
| `chat_groups` | `id, name, icon, owner_id, public, join_approval, description, created_at, frozen_at, dissolved_at` |
| `chat_members` | `group_id, user_id, nickname, joined_at, muted_until, notify(all\|mentions\|none\|null)` |
| `chat_roles` | `id, group_id, name, color, permissions(i64), position, mentionable` |
| `chat_member_roles` | `group_id, user_id, role_id` |
| `chat_channels` | `id, group_id(null 为私信), kind, name, topic, parent_id, position, slow_mode_s, voice_bitrate, voice_limit, created_at` |
| `chat_overwrites` | `channel_id, role_id, allow(i64), deny(i64)` |
| `chat_dm` | `channel_id, user_a, user_b`（`user_a < user_b`，唯一） |
| `chat_messages` | `id, channel_id, author_id, content, reply_to, mentions(json), attachments(json), pinned_at, edited_at, deleted_at` |
| `chat_messages_fts` | FTS5（`tokenize='trigram'`），`rowid = 消息 id`，只放 `content` |
| `chat_attachments` | `id, owner_id, channel_id, group_id, name, mime, size, width, height, sha256, created_at, message_id(null 为待发送)` |
| `chat_read_states` | `user_id, channel_id, last_read_id, mentions` |
| `chat_bans` | `group_id, user_id, by, reason, at` |
| `chat_invites` | `id(code), group_id, by, max_uses, uses, expires_at, revoked_at` |
| `chat_join_requests` | `group_id, user_id, via(invite\|public), at` |
| `chat_group_invites` | `id, group_id, user_id, by_user, at`（拉好友入群、待对方接受） |
| `chat_audit` | `group_id, actor_id, action, target, details(json), at` |
| `chat_prefs` | `user_id, prefs(json)`（通知设置、勿扰时段、隐藏通知内容、已读回执开关等，整份按账号同步） |
| `users` 加列 | `avatar`（图片文件名）、`status(online\|idle\|dnd\|invisible)` |
| `devices` 加列 | `x25519`（设备的 X25519 公钥，§10.1） |

- 删除消息只置 `deleted_at` 并清空 `content` 与附件（界面显示“消息已撤回”占位）；对应的附件文件立即删除。
- 群组解散置 `dissolved_at`，成员立即看不到；30 天内群主或服务器管理员可恢复，之后后台任务删除群组的所有行与文件。
- 账号停用或删除后，其消息保留，作者显示为“已停用的账号”。

### 2.4 附件存储

- 文件在数据目录 `attachments/<群组 id 或 dm>/<附件 id>`；图片另存缩略图 `…/<附件 id>.thumb.webp`（长边 ≤ 400 像素）。
- 上传分两步（签名请求要缓冲主体，大文件不走它）：`POST /chat/attachments {channel_id, name, mime, size}` 按频道检查“上传附件”权限、单文件上限、群组容量（私信算发送者的个人配额），回执附件 ID 与上传地址 `/media/upload/{id}?t=<一次性令牌>`；客户端对它 `PUT` 原始字节（不签名），服务端流式写入、边写边算 SHA-256，字节数必须与声明一致。1 小时内没有被消息引用的附件被清理。
- 图片：服务端读取尺寸并生成缩略图，解码前检查像素数（≤ 50 MP），防解压炸弹；动图只取第一帧做缩略图。
- 下载走 `/media/...`，以查询参数里的媒体令牌认证（浏览器的 `<img>` 不能加签名头）：`POST /chat/media-token`（账号）→ `{token, expires_at}`，一天有效，HMAC 密钥存在数据库里，重启不失效。`GET /media/attachments/{id}/{name}?t=`（能看到该频道，且在 `read_history` 规则内）、`GET /media/thumbs/{id}?t=`；服务端解码过的图片内联并带原类型，其余 `Content-Disposition: attachment` 与 `application/octet-stream`（`&download=1` 强制下载）；`X-Content-Type-Options: nosniff`、`Content-Security-Policy: sandbox`、支持 `Range`。
- 头像与群图标：`PUT /me/avatar`、`PUT /chat/groups/{id}/icon`（签名请求，原始字节 ≤ 4 MiB，PNG / JPEG / WebP / GIF 取第一帧），服务端裁成正方形 256 像素 WebP，回执新的版本号；`GET /media/avatars/{user_id}?v=&t=` 与 `GET /media/icons/{group_id}?v=&t=`，按版本号长期缓存。

## 3. 权限

### 3.1 权限位

| 位 | 名称 | 说明 |
| --- | --- | --- |
| 0 | `view` | 看到频道并读消息（语音频道：看到并能看在场的人） |
| 1 | `send` | 发消息（公告频道默认只有管理者有） |
| 2 | `attach` | 上传附件 |
| 3 | `mention_all` | @全体、@在线 |
| 4 | `manage_messages` | 删除他人消息、置顶 |
| 5 | `read_history` | 读加入前的历史（关掉时只能看到自己能看见该频道之后的消息） |
| 8 | `connect` | 进语音频道 |
| 9 | `speak` | 在语音里说话 |
| 10 | `video` | 开摄像头、共享屏幕 |
| 11 | `voice_moderate` | 服务器静音 / 关闭他人声音、移动到其他语音频道、断开 |
| 12 | `priority` | 语音人数已满时仍能进入 |
| 16 | `invite` | 生成邀请链接、拉好友入群 |
| 17 | `kick` | 踢出 |
| 18 | `ban` | 封禁与解封 |
| 19 | `mute` | 文字禁言 |
| 20 | `manage_channels` | 建、改、删频道与分类，改频道的角色覆盖 |
| 21 | `manage_roles` | 建、改、删角色，给成员加减角色（只能管理排在自己最高角色之下的角色） |
| 22 | `manage_group` | 改群组名称、图标、公开与审批设置，审批加入申请，查看群组审计日志 |
| 30 | `administrator` | 拥有全部权限，不受频道覆盖限制 |

- `@everyone` 默认：`view, send, attach, read_history, connect, speak, video, invite`。
- 新建群组时另建一个“管理员”角色（`administrator`），群主自动拥有一切权限且不能被移出群组。

### 3.2 计算

成员在某频道的权限：

1. 群主或有 `administrator` → 全部。
2. 基础 = `@everyone` 的权限 ∪ 成员所有角色的权限。
3. 依次应用该频道所在分类的覆盖、频道自己的覆盖（频道没有自己的覆盖时继承分类）：先 `@everyone` 的 `deny`、`allow`，再成员所有角色的 `deny` 的并集、`allow` 的并集。
4. 没有 `view` 时其余全部视为没有；被禁言时去掉 `send`、`attach`、`speak`；群组被冻结时只剩 `view`、`read_history`。

私信：双方都有 `view, send, attach, read_history, connect, speak, video`；解除好友后私信只读，不能再发消息或通话。

服务器管理员不在群组里时没有任何频道权限；他在控制台的操作见 §13。

## 4. 文字

### 4.1 消息内容

- `content`：≤ 4000 个字符（Unicode 标量），去掉首尾空白后不能为空（有附件时可以空）；每条最多 10 个附件。超长时客户端提示字数，粘贴的大段文本可一键转为 `.txt` 附件。
- Markdown 子集（两端各自渲染，服务端不解析格式）：`**粗**`、`*斜*` / `_斜_`、`~~删除线~~`、`` `行内代码` ``、```` ``` ```` 代码块（可带语言名，不做语法高亮）、`> 引用`、`||剧透||`、自动识别的链接与 `[文字](地址)`（悬停显示真实地址）、`\` 转义。不支持标题、表格、图片语法与 HTML。
- 提及：`<@用户 id>`、`<@&角色 id>`、`<@everyone>`、`<@here>`（@在线），频道链接 `<#频道 id>`。服务端解析出提及对象存入 `mentions`（只收有 `mention_all` 权限者的 @全体 / @在线，只收 `mentionable` 或有 `mention_all` 者的角色提及），用于未读与通知。
- 回复：`reply_to` 指向同一频道的消息；显示被回复者与内容摘要（已删除的显示“原消息已撤回”），点击跳转。回复默认提及被回复者（发送前可关）。
- emoji：消息里就是 Unicode 字符；两端把 emoji 序列（含 ZWJ 组合、肤色）换成 Fluent Emoji 平面风格图片显示。只有 emoji（≤ 27 个）的消息放大显示。

### 4.2 编辑、撤回、置顶

- 作者可随时编辑（显示“已编辑”）与撤回；有 `manage_messages` 的人可撤回他人消息（记入群组审计日志），不能编辑他人消息。
- 置顶：`manage_messages`；每个频道最多 50 条；频道顶部“置顶消息”列表。私信双方都能置顶。

### 4.3 搜索

- 服务端 FTS5 `trigram` 索引 `content`（发送、编辑、撤回时同步）。查询词三个字符及以上走索引，一两个字符的在调用者能看到的频道里倒序扫描（每次最多扫 20000 条）。
- 条件：关键词、作者、频道（或群组、私信）、时间范围、有附件。只返回调用者现在有 `view`（及 `read_history` 规则）的频道里的消息，按时间倒序分页。

### 4.4 未读、已读与提及

- 每个账号每个频道记 `last_read_id` 与未读提及数；读到哪里由客户端上报（停留在频道底部 1 秒、或打开频道时），同一账号的所有设备同步。
- 频道列表：有未读的频道名加粗；有提及的显示数字。群组头像：有未读显示小点，有提及显示数字。消息区有“新消息”分隔线与“跳到第一条未读”；“全部标为已读”按群组或全局。
- 私信已读回执：对方的 `last_read_id` 推给我，在我最后一条已读的消息下显示“已读”；任一方在个人设置里关掉回执时，双方都不再显示（像多数聊天软件）。

### 4.5 正在输入、在线状态

- 正在输入：客户端在输入时每 4 秒至多发一次 `chat.typing{channel}`；服务端转给有 `view` 的在线成员，客户端显示 8 秒。不存储。
- 账号在线状态：账号有任一设备的聊天连接在线即为在线；所有在线设备都上报空闲（10 分钟无输入）即为离开；用户可手动设勿扰或隐身（隐身对他人显示为离线）。勿扰时不弹通知、不响提示音（来电仍有未接记录）。状态推给好友与有共同群组的人。

### 4.6 通知

- 每个群组、每个频道可设“所有消息 / 仅 @ / 静音”（频道不设时跟随群组；群组默认“仅 @”，私信默认“所有消息”）；另有每天的勿扰时段（如 23:00–08:00），由客户端按本机时间判断。
- 弹窗显示“群组 · 频道”或私信对方、发送者与前 60 个字的摘要；个人设置可改为只显示“有新消息”。点击打开对应位置。
- 原生用现有的 Windows 通知（或窗口内卡片）；网页用浏览器通知（需授权）。聊天消息不写入现有的 `notices` 表。

### 4.7 防刷屏与慢速模式

- 服务端对每个账号限速：5 秒内最多 5 条（服务器设置可调），超出回 `429`，客户端提示稍后再发。
- 慢速模式：频道设置 `slow_mode_s`，每人每 N 秒一条；有 `manage_messages` 的人不受限。

## 5. 群组、成员与管理

- 建群组：服务器设置“允许用户创建群组”开时任何用户可建，关时只有管理员；建好时带一个分类“文字频道”、一个文字频道“综合”、一个语音频道“语音”。
- 加入：
  - 邀请链接：`有 invite 权限` 的成员生成，可设次数（1–100 或不限）与有效期（30 分钟–永久），可作废，记使用者；链接形如 `https://<服务器>/chat/invite/<code>`：网页直接打开；原生在“加入群组”里粘贴链接或邀请码。
  - 拉好友：有 `invite` 权限的成员把好友拉进来，对方收到邀请（在私信区显示），接受后加入。
  - 公开群组：群主可设为公开，服务器内用户在“发现”中按名称搜到并加入。
  - 审批：群组开“加入需审批”时，经邀请链接或“发现”的加入先成为申请，有 `manage_group` 的人批准或拒绝；拉好友（已由有权限的人发起）不需要审批。
- 封禁的账号不能再加入（包括经邀请链接）。退出群组：群主须先转让。
- 群组审计日志：踢出、封禁、解封、禁言、语音管控、撤回他人消息、置顶、频道与角色变化、群组设置变化、邀请生成与作废、审批。保留期与服务器审计日志相同。

## 6. 接口

### 6.1 聊天连接

聊天走单独的实时连接，与远程桌面的在线连接（由被控进程或后台服务持有）分开：设备中心与网页各自持有一条，不受“允许被控”与后台服务影响。

- `POST /chat/ticket`（账号）→ `{ticket, endpoints}`；`GET /ws?ticket=` 建立的连接角色为 `chat`。同一设备同时只有一条聊天连接（新的取代旧的，`4001`），与它的在线连接互不取代；登录被撤销时关闭（`4003`）。
- 信封、心跳与重连同 farwing-protocol §4.2–4.4；聊天连接不恢复（`hello` 里没有恢复令牌），断开后用新票据重连，重新取快照。`GET /chat/state` 以 HTTP 回执同样的快照。
- 连接建立后客户端发 `chat.hello{status, idle}`，服务端回 `ack{snapshot}`：自己的群组、频道、角色、成员数、未读状态、私信列表、好友在线状态、各语音频道在场的人。之后的变化都以推送到达。

## 7. 语音

### 7.1 进入与离开

- `POST /chat/channels/{id}/voice/join {self_muted, self_deafened}`（按发请求的设备）：检查 `connect`、人数上限（`priority` 可越过）、出口策略（§11）。回执：节点、ICE 服务器、本设备在频道里的参与者编号、在场的人、各人的帧密钥分发所需的 X25519 公钥（§10）。
- 同一账号可以用多台设备同时在同一或不同的语音频道里（每台设备一个参与者）；同一设备进别的频道时自动离开原来的。
- 离开：`POST /chat/channels/{id}/voice/leave`，或聊天连接断开 30 秒未恢复，或媒体连接 20 秒没有任何包。

### 7.2 节点

- 每个语音频道在第一个人进入时选定一个转发节点：控制节点与各中转节点里出口未满的（[egress-policy.md](egress-policy.md) §4.5），优先本服务器；频道清空后释放。
- 同一频道的人都连到这个节点；节点间级联以后再做。节点离线时频道里的人收到 `voice.moved`，重新进入另一个节点。

### 7.3 媒体连接

每个参与者到节点两条连接，复用现有转发器（`server/src/sfu`），扩展为多人上行：

- **上行**（客户端发起协商）：发自己的声音（`mic`），按需加摄像头两路（`cam_hi`、`cam_lo`）、共享的画面与声音（`screen`、`screen_audio`，有观众选 720p30 时另加 `screen_720`）。增减轨道时客户端重新发 offer（`PUT /chat/channels/{id}/voice/publish`），服务端 answer。
- **下行**（服务端发起协商）：服务端把要发给这位参与者的轨道组成 offer，经聊天连接 `voice.offer{generation, sdp}` 推下，客户端回 `voice.answer`。默认订阅：在场所有人的 `mic`（全部转发，不筛选）；摄像头按布局订阅大或小一路；屏幕共享在观众点开后才订阅（`PUT /chat/channels/{id}/voice/subscribe {tracks}`）。
- **轨道映射**：`voice.tracks{generation, tracks: [{mid, participant, kind}]}` 告诉客户端每条下行轨属于谁、是什么；客户端以此显示与解密（每个发送者一套帧密钥）。
- 转发器对每条上行轨按需转给订阅者，回应 NACK、合并关键帧请求，沿用现有转发的做法；不把一个参与者自己的轨发回给他。
- 说话指示：发送端在 RTP 头扩展中带声音电平（RFC 6464，`ssrc-audio-level`，加密不影响），接收端据此显示谁在说话。

### 7.4 声音

- **编码**：Opus 48 kHz，单声道人声（频道码率 ≥ 96 kbps 时双声道），20 ms 帧，打开 DTX（静音不发包）与带内 FEC；码率取频道设置（服务器设置“语音最高码率”为上限），网络差时按丢包与反馈自动降到 24 kbps。
- **接收与播放**：每个发送者一个抖动缓冲（复用现有 NetEq 桥接），解码后混音，经 WASAPI 播放到“通话输出设备”（默认跟随系统默认设备）。每人的音量可单独调（0–200%），可单独静音某人；“关闭声音”即不播放也不发送。
- **采集与处理**：麦克风经 WASAPI 采集，送入 WebRTC 音频处理模块（AEC3 回声消除，参考信号为本机即将播放的通话混音；降噪普通 / 强两档；数字增益控制；高通），用与 NetEq 相同的 C++ 桥接方式编进客户端。“AI 降噪”一档用 RNNoise 的 Rust 移植（nnnoiseless，BSD）代替 WebRTC 的降噪。网页用浏览器的 `echoCancellation`、`noiseSuppression`、`autoGainControl`。
- **说话方式**：
  - 语音激活：处理后的电平超过阈值开始发送、低于阈值 400 ms 后停止；阈值可自动（按底噪）或手动（设置里有电平条）。
  - 按键说话：全局快捷键（键盘或鼠标侧键），按住发送，松开后 200 ms 停止；原生用 Raw Input（`RIDEV_INPUTSINK`）在后台也能收到，不装钩子；游戏以管理员身份运行时 Windows 不把输入给非提权程序（与其他聊天软件相同，界面提示）。网页的按键说话只在页面有焦点时生效。
  - 全局“静音”“关闭声音”快捷键。
- **不压低其他声音**：Windows 在通信类声音流打开时会自动压低其他程序；通话的采集与播放流不标为通信类，并对会话设置不参与压低。
- **设置**：输入、输出设备（与远程桌面的声音设备分开）、输入音量与电平条、麦克风测试（录 5 秒回放）、降噪档位、说话方式与快捷键、提示音逐项开关与音量。

### 7.5 提示音

来电铃声、新消息、有人进出我所在的语音频道、自己静音 / 关闭声音、开始 / 结束直播、被移动或断开。都由设备中心（网页由页面）播放，因此属于 §9 中被排除的 Farwing 声音。

### 7.6 私信通话

- **呼叫**：`POST /chat/dm/{channel}/call` → 服务端生成通话 ID，向对方所有在线设备推 `call.ring{call, from, video}`，向自己的其他设备推 `call.outgoing`；45 秒无人接听即 `call.missed`（私信里留一条“未接通话”）。勿扰或勿扰时段内不响铃、只留未接。
- **接听**：`POST /chat/calls/{call}/answer`（第一台接听的设备；其他设备收到 `call.answered_elsewhere` 停止响铃）；拒绝 `…/decline`；挂断 `…/hangup`；转到这台设备 `…/move`（原设备退出）。
- **媒体**：两台设备之间点对点，信令沿用 `rtc.offer` / `rtc.answer` / `rtc.candidate`（以通话 ID 为 `sid`），NAT 穿透与中转沿用远程桌面（farwing-protocol §7）；双方都发送与接收声音（与摄像头、共享）。端到端加密同 §10（两人的帧密钥直接在两台设备的已认证连接上交换）。
- **通话中**：私信里显示通话条（时长、静音、关闭声音、摄像头、共享、挂断）；任一方结束即结束。通话记录写入私信（“通话 12 分钟”）。

### 7.7 后台通话

关掉设备中心窗口时通话（语音频道或私信通话）继续：托盘图标标出通话中，右键菜单有静音、关闭声音、挂断 / 离开、回到窗口；来电与消息通知照常。退出设备中心（托盘“退出”）即离开所有通话。

## 8. 摄像头与屏幕共享

### 8.1 摄像头

- 原生用 Media Foundation 采集（偏好 1280×720@30，NV12 或 MJPEG 解码），经现有编码器（硬件优先，回退到软件 H.264）编两路：`cam_hi` 720p30 上限 1.2 Mbps、`cam_lo` 320×180@15 上限 80 kbps。摄像头采集与参数沿用远程摄像头（[camera-design.md](camera-design.md) §3）。网页用 `getUserMedia`，同样发两路（第二路为同一轨道的克隆，`scaleResolutionDownBy: 4`）。
- 观看：宫格时订阅小路，放大或“发言人”布局时订阅大路；切换时先收到新一路的关键帧再换（沿用转发的不断画切换）。

### 8.2 屏幕共享（原生）

- **来源**：
  - 整个屏幕：现有桌面采集（DXGI Desktop Duplication），声音为系统声音（§9）。
  - 单个窗口：Windows Graphics Capture 采集窗口（窗口被遮挡时照常，最小化时画面停在最后一帧并显示“窗口已最小化”）；声音只取该窗口所属程序（§9）。Windows 11 上去掉黄色采集边框。
  - 每种都可以选“不带声音”。
- **画质**：共享者选 720p 或 1080p、30 或 60 帧，共享中随时切换（同一编码器重配，不断开）；按画面内容动态码率，上限 720p30 3 Mbps、720p60 4、1080p30 4、1080p60 6。
- **观众选 720p30**：共享者开的不是 720p30 时，网络差的观众可在观看画质里手动选“720p30”；有人选时共享者才多编这一路（`screen_720`，上限 3 Mbps），没人选时停掉。服务器不自动给观众换路，也没有更低的一路；转发器只按观众的选择转发。
- **编码与发送**：复用被控的采集、编码组与发送路径（`features/host` 的编码组、RS-FEC、恢复帧、拥塞控制），共享是这台设备上的又一个“上行成员”；同一台设备此时正被远程观看时，相同屏幕与格式的编码可以共用。
- **观看**：观众点开某人的直播后订阅 `screen`（与 `screen_audio`）；聊天页内嵌显示（宫格或放大），可弹出独立窗口（复用现有观看窗口的解码与呈现，支持全屏）。网页只显示一路主画面。
- 一个语音频道里可以多人同时共享，频道列表里在名字旁标“直播中”。

### 8.3 请求控制

- 观众（原生或网页）在共享画面上点“请求控制”：`POST /chat/channels/{id}/voice/control-request {sharer_device}`；共享者回答 `POST …/voice/control-request/{request}/answer {allowed, clipboard}`；共享者的设备中心弹窗“某某请求控制你的屏幕”：允许 / 拒绝，可勾选“允许剪贴板”。
- 同意后服务端为这位观众记一个临时授权（关系 `share`，能力 `view, control, annotation`，可加 `clipboard`），观众随即对共享者的设备发起一个普通的远程桌面会话（点对点，键鼠走数据通道，延迟低），弹出的观看窗口改为这个会话的画面。
- 共享者的被控收到关系为 `share` 的会话时，按服务端给的能力授权，不要求“允许被控”（共享者已当面同意）；只在这台设备正在共享时接受。共享者结束共享、点“收回控制”或离开语音时，服务端撤销授权，会话以 `permission_revoked` 结束。
- 只对“整个屏幕”的共享可用（窗口共享的坐标映射与遮挡不可靠）。

## 9. 防回环

### 9.1 问题

共享系统声音时用的是整机的声音回环采集，会把本机正在播放的通话声音也录进去：别人在直播的声音里又听到自己和其他人的说话声。同理，远程桌面被控采集桌面声音时，控制者会听到被控正在进行的通话。

### 9.2 按进程排除（Windows 10 Build 20348 起，即 Windows 11）

- 用应用回环采集：`ActivateAudioInterfaceAsync`（`VIRTUAL_AUDIO_DEVICE_PROCESS_LOOPBACK`）加 `AUDIOCLIENT_PROCESS_LOOPBACK_PARAMS`：
  - 整屏共享：`PROCESS_LOOPBACK_MODE_EXCLUDE_TARGET_PROCESS_TREE`，目标为设备中心的进程，采到除 Farwing 声音以外的全部系统声音。
  - 窗口共享：`PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE`，目标为窗口所属进程，只采这个程序（及其子进程）的声音。
- 前提：所有通话声音、提示音、聊天页内嵌播放的直播与摄像头声音都在设备中心进程（或其子进程）里播放。
- 应用回环采集没有混音格式可查，请求 48 kHz、双声道、浮点，直接进入现有的 Opus 编码。

### 9.3 老系统：参考信号抵消

- 设备中心保存最近 2 秒实际交给播放设备的通话混音（含提示音），带音频引擎时间戳（`IAudioClock` 位置与 QPC）。
- 整机回环采集到的每块声音带 QPC 时间戳，按时间对齐后把对应的参考信号送入一个独立的 AEC3 实例（远端 = 参考，近端 = 回环），输出作为共享的系统声音。回环里的通话声是数字副本，没有房间回声，通常能消得很干净。
- 抵消不干净（系统音效、空间音效等非线性处理）时不做别的，照常发送采集到的声音（已确定接受可能的回声）。
- 老系统上的窗口共享取不到单个程序的声音，改为“系统声音去掉通话声”（共享面板上写明“将共享系统声音”）。

### 9.4 远程桌面被控

- 被控设置新增“远程观看时排除本机 Farwing 通话的声音”（默认开）。
- 开着时，被控的桌面声音采集改为按进程排除，目标为本机设备中心的进程（装了后台服务时，后台服务在用户会话中的采集进程经现有的进程间通道得知设备中心的进程 ID）；老系统用 §9.3 的抵消，参考信号由设备中心经同一通道提供。设备中心没有通话时照常采集。

### 9.5 其他

- 转发器不把一个人自己的轨发回给他；人声与共享的声音是不同的轨，接收方可分别调音量。
- 同一账号在同一频道的多台设备之间声音照常转发（已确定），放在一起外放会形成声学回环，由使用者自己避免（界面在第二台设备进入同一频道时提示一次）。

## 10. 端到端加密

### 10.1 设备的 X25519 密钥

- 每台设备（原生与网页）新增一个 X25519 密钥对，私钥与现有 Ed25519 私钥放在一起（原生：系统凭据存储 / 服务保险库；网页：不可导出的 WebCrypto 密钥，浏览器不支持 X25519 时用 `@noble/curves` 并存入 IndexedDB）。
- 公钥在 `POST /devices/init` 中登记（已登记的设备用新接口 `PUT /devices/self/x25519`），附 Ed25519 签名 `"FWX25519\n" + x25519_public`；服务端存入 `devices.x25519`。

### 10.2 语音频道与私信通话的帧密钥

- 每个参与者进入时生成自己的帧密钥（20 字节，格式同 farwing-protocol §6.8）与 `key_id`。
- 分发：对在场的每台设备，用对方的 X25519 公钥做 ECDH（本方临时密钥），HKDF-SHA256 得到包裹密钥，AES-256-GCM 包裹 `{frame_key, key_id, participant}`；整体用本设备 Ed25519 签名。经 `POST /chat/channels/{id}/voice/keys` 交给服务端，服务端以 `voice.keys` 推给各接收设备；接收方核对签名与发送者身份（设备 ID 与公钥一致，§2.1）后保存。
- 换钥：有人离开时，留下的每个人生成新密钥并分发，2 秒后改用新密钥；有人进入时，在场的人把当前密钥分发给他（不换钥）。接收方为每个发送者保留最新两个密钥。
- 帧加密格式、加密单元与失败处理同 farwing-protocol §6.8，只是每个发送者各有密钥与 counter。网页用编码帧变换（`RTCRtpScriptTransform`）加解密。
- 私信通话两台设备点对点，帧密钥在双方已认证的连接上直接交换（与直连 DTLS 绑定相同的身份校验）。

### 10.3 范围与限制

- 服务端只转发密文：看不到画面与声音内容，能看到声音电平、包大小与时间。
- 文字消息与附件不在端到端加密范围内（服务端明文）。
- 网页的端到端加密依赖浏览器的编码帧变换；不支持的浏览器只能进入兼容模式的语音频道。

### 10.4 兼容模式

- 服务器“端到端加密”为“允许兼容”时，群主可把某个语音频道设为兼容模式（频道设置，默认端到端）；为“强制”时只有端到端；为“关闭”时所有频道都是兼容模式。
- 兼容模式：不做帧加密（媒体仍经 DTLS-SRTP 到转发器），转发器能读到媒体，为以后的服务端录制、转码留门；频道名旁与通话条上标明“兼容模式”。
- 客户端设置“只接受端到端加密”打开时，不进入兼容模式的频道（提示原因）。
- 私信通话点对点，始终是两端之间的 DTLS-SRTP 加密，不受这些设置影响；经中转时也一样。

## 11. 流量与出口策略

- 语音频道与共享经转发器：每条下行算接收者账号的（[egress-policy.md](egress-policy.md) §2 的“转发”计量），受该账号的速率上限与月配额约束；节点出口满时转发器先压低视频（摄像头与共享），声音不压。
- 用户策略的“多人转发”关闭时：不能进入语音频道（`403 chat_forbidden`，提示“你的账号不能使用多人转发”）；私信通话仍可点对点。
- 私信通话经中转时，按方向计给接收的一方。
- 月配额用完：已在语音里的人可以继续听声音，不能再订阅摄像头与共享；新的进入被拒。

## 12. 客户端

### 12.1 原生设备中心

- 侧栏新增“聊天”。页面四栏：群组头像栏（最上为私信，下为各群组，加号建群组 / 加入，指南针为“发现”）；频道列表（分类可折叠，语音频道下列出在场的人与直播标记，底部为语音状态条与自己的头像、静音、关闭声音、设置）；消息区（顶部频道名、话题、置顶、搜索、成员按钮）；可收起的成员列表（按角色分组、在线在前）。语音频道打开时消息区上方为画面区（宫格 / 放大）。
- 消息列表：可变高度的虚拟列表（只布局可见区与缓存高度），向上滚动加载更早的消息，跳转到某条时以它为中心加载。
- 输入框：多行、输入法、`@` 与 `:` 补全（成员、角色、频道、emoji 名称）、粘贴图片与拖入文件即为附件、回复与编辑状态、超长提示。
- Markdown 用 `pulldown-cmark` 解析后按 §4.1 的子集排版；emoji 图片按需向服务器取（服务器随网页资源提供，§12.3）并缓存在本机。
- 图片：缩略图内联，点开为可缩放的查看器；其他附件显示名称、大小与下载。
- 本地缓存：每个频道最近 200 条消息与缩略图，存在 profile 目录，用 Windows 凭据保护的密钥加密；启动与切换频道时先显示缓存再刷新；退出登录时清除。
- 好友页：每个好友加“私信”“语音通话”按钮，显示账号在线状态。私信顶部列出对方授权给我的设备，可直接连接（沿用现有好友授权）。
- 外部链接：打开前弹窗显示真实地址（可勾选“以后信任此域名”）。

### 12.2 网页

同一套四栏布局与功能（React），语音与摄像头用浏览器 WebRTC，端到端加密用编码帧变换 Worker（扩展现有的 `forwardWorker.ts`）。不提供共享屏幕；观看共享只显示一路主画面。按键说话只在页面有焦点时有效。浏览器通知需用户授权。

### 12.3 emoji 资源

服务端构建网页时把 Fluent Emoji 平面风格 SVG 转为 72 像素 PNG（`resvg`），随网页资源嵌入，`GET /emoji/<码点序列>.png`；附带 emoji 名称与关键词表（中英）供选择器搜索。两端都从这里取，原生缓存到本机。

## 13. 服务器设置与控制台

- 服务器设置新增“聊天”一组：允许用户创建群组、单个附件上限（默认 100 MB）、群组默认容量（默认 10 GB，可按群组单独调）、个人私信附件配额（默认 5 GB）、消息保留天数（默认永久）、发消息频率（默认 5 秒 5 条）、语音最高码率（默认 128 kbps）。
- 控制台新增“群组”页：名称、群主、成员数、频道数、存储用量、创建时间、状态；可冻结 / 解冻、解散 / 恢复、转让群主、调整容量，查看群组审计日志。不提供浏览消息内容的界面。
- 服务器审计日志记录管理员对群组的操作。

### 实施中再定的细节

- 私信通话的画面（2026-11-02 定）：两边按同样的顺序一次协商四段（麦克风、摄像头、共享、共享的声音），开关画面不再协商，收到的轨道按所在的段认种类；通话里的画面只用 H.264。
- 被控排除通话声（2026-11-02 定）：采集跟随默认输出时生效，按设备中心窗口的标记找到它的进程；老系统不做参考抵消，照常整机采集。

- 原生消息列表（2026-11-01 定）：只画可见的行（按测得的行高定位，未测的行按估计），图片纹理按需加载；复制用消息工具栏的“复制文字”（egui 的富文本不做跨段选中）。
- 声音处理（2026-11-01 定）：不另带 WebRTC 音频处理模块的源码，麦克风的回声消除、降噪与增益用 Windows 自带的语音处理（语音捕获 DSP，参考信号为系统正在播放的声音，对所有 Windows 版本可用），“AI 降噪”一档用 nnnoiseless；老系统上共享的系统声音不做参考抵消，照常采集（§9.3 已接受可能的回声）。
- 私信通话（2026-11-01 定）：点对点 DTLS，双方设备用 Ed25519 签名各自描述里的 DTLS 指纹（`call_signal_message`），不另加帧密钥。
- 设备密钥（2026-11-01 定）：原生的 X25519 密钥由设备的 Ed25519 种子经 HKDF 派生，不另存；网页端的存在 IndexedDB，第一次进语音时登记。
- 按键说话（2026-11-01 定）：原生轮询按键状态（焦点在任何程序都可用，鼠标侧键也行）；网页端只在页面有焦点时。
- 连接与保活（2026-11-01 定）：连转发器只等 300 ms 收集候选，私信通话最多 3 秒；不说话时每 25 帧发一个静音包，转发器以 RTP 或 RTCP 判断在线，20 秒什么都没有才移出。
- 用词（2026-11-01 定）：“闭麦”改称“关闭声音”（不播放也不发送），与“静音”区分。
- 按设计核对后补齐（2026-11-01 定）：
  - 管理员“关闭其声音”在转发器上执行（不再转发给他，他的声音也不转发）；被禁言等失去 `speak` 时转发器不再转发他的声音（参与者带 `cannot_speak`，界面显示为被静音）。
  - 节点连续两次（约 10 秒）不应答时，控制节点让频道里的人重新进入（`voice.moved` 不带 `to`），重新选节点。
  - 月流量用完时进入被拒的原因为 `voice_quota`（“本月流量已用完”），与“不能使用多人转发”区分。
  - 网页端每人与输出音量为 0–100%：播放用媒体元素，浏览器的回声消除才听得到；原生仍为 0–200%。
  - 提示音音量为输出音量的百分比；每类提示音单独开关。
  - 按键说话的提权提示：前台程序以管理员身份运行而设备中心没有时，语音条显示一行提示（随前台变化）。
  - 不压低其他声音：语音会话打开前对本进程在语音设备上的会话设置不参与压低（`SetDuckingPreference`）。
- 窗口采集在多显示器与 DPI 缩放下的坐标与尺寸处理。
- 语音频道节点故障时的重连细节与参与者编号的稳定性。
