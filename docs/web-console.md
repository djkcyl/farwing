# Farwing Server 网页端

状态：已实施（2026-10-17，阶段 0–6）。范围：服务器自带的网页端——用户中心、管理后台与浏览器里的远程桌面（观看，以及按授权的键鼠、剪贴板、文件与麦克风）。本机验证结果见 [selftest-results.md](selftest-results.md) §11，需要其他环境的检查见 [manual-test-checklist.md](manual-test-checklist.md) 第 22 节，部署说明见 `server/README.md`“网页端”。浏览器端的协议依据见 [protocol/web-viewer-brief.md](protocol/web-viewer-brief.md) 与 [protocol/web-control-brief.md](protocol/web-control-brief.md)。

## 1. 已确定的决定

| 问题 | 决定 |
| --- | --- |
| 给谁用 | 管理后台（管理员）+ 用户中心（所有账号） |
| 浏览器远程 | 第一期做观看并尽量做全；第二期（阶段 6）按授权控制：权限与客户端完全相同，服务器可以在线限制网页端能用的功能（只勾观看与声音即只看不控）；键鼠、文本剪贴板、文件传输、麦克风；全屏时锁定键盘并提供特殊键菜单；支持触屏 |
| 网页观看能连谁 | 本账号与好友共享的设备（账号身份），以及短号 / 设备 ID + 访问码或对方确认的访客观看（无需账号） |
| 前端 | React + TypeScript + Vite，组件自绘，外观与客户端一致（客户端的深色配色） |
| 账号产生 | 管理员创建；可选邀请码注册（默认关闭） |
| 后台访问 | 默认不限 IP（配置里可加白名单）；管理员可开启 TOTP 二次验证 |

## 2. 实施前的状况

- 服务端没有网页：只有 `/healthz` 与客户端用的 `/api/v2/*`。
- 管理只能在服务器上用命令行（`user`、`device`、`session`、`friend`），命令行写入 `admin_events`，由运行中的服务实时生效。
- 账号没有角色，不开放注册；配置与客户端更新公告只在配置文件中。

## 3. 构建与部署

- 前端工程在 `server/web/`，`npm run build` 输出到 `server/web/dist/`。依赖全部装在 `server/web/node_modules/`，页面不引用 CDN 或外部资源。前端检查：`npm run check`（tsc、oxlint、Prettier、Vitest）。
- 编译服务端时 `server/build.rs` 把 `dist/` 嵌进二进制（`web_static.rs` 提供，单页应用回退到 `index.html`，`/assets/` 长期缓存）。构建时为文本资源生成 Brotli 与 gzip 副本（`scripts/compress.mjs`），服务端按 `Accept-Encoding` 返回并带 `Vary`。`cargo build` 不调用 npm；没有 `dist/` 时网页显示“网页端没有构建”。
- `server/build-web.ps1` / `build-web.sh`：`npm ci` → `npm run check` → `npm run build` → `cargo build --release --locked`。Dockerfile 增加 Node 构建阶段。
- 同一端口、同一 TLS：`/` 为网页（前端路由），接口仍在 `/api/v2/*`（没有另设 `/api/v2/web/*` 前缀，见 §8）。
- 带路径前缀的反向代理：页面使用 `<base href>` 与相对资源路径，服务端按 `public_url` 的路径写入 `<base>`；前端的接口、路由与实时连接都相对于它。
- 配置 `[web]`：`enabled`（默认开）、`admin_allow`（后台 IP 白名单）、`session_idle_minutes`（30）、`session_max_hours`（12）、`audit_days`（180）。
- 响应头：CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' blob:; connect-src 'self' wss: ws:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`，以及 `X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy: no-referrer`、`Permissions-Policy`。

## 4. 账号、登录与安全

### 4.1 浏览器即设备（取代原提案的 Cookie 会话）

原提案用 HttpOnly Cookie 会话加 CSRF 校验。实施时改为让浏览器作为一台平台为 `web` 的 Farwing 设备，复用客户端的接口与签名，理由：观看本来就需要设备密钥（DTLS 身份签名），一套凭据即可；签名请求不依赖 Cookie，没有 CSRF 面。

- 浏览器生成 Ed25519 设备密钥：优先 WebCrypto（不可导出，存 IndexedDB）；不支持时用 `@noble/curves`（种子存 IndexedDB）。设备 ID 由公钥推导，名称如“Chrome · Windows”（不含界面语言；平台“网页”在显示时另列）。
- 每个请求与客户端一样签名（`FWREQ2`，设备 ID、时间戳、签名头），时间戳在页面内严格递增（同一毫秒的相同请求签名不同，避免被当作重放）。
- 登录令牌放在 `localStorage`（多个标签页共享）；没有这个浏览器的私钥，令牌不能使用。网页设备的登录空闲 `session_idle_minutes`、最长 `session_max_hours` 后失效（客户端登录不受影响），在“我的登录”中可单独注销。远程会话进行中（画面播放或正在恢复）每 5 分钟用一次 `GET /api/v2/me` 保持登录，所以看着、控制着不会因空闲过期；这个请求即使遇到登录失效也不会把页面退出到登录页（会话继续，之后的普通请求再提示），最长期限照常生效。
- 登录限流沿用 `login_failures_per_ip/per_user`；改密码、禁用、删除账号时撤销该账号的所有登录（含网页）。
- 已登录接口对“密码 / 验证码不正确”返回 403，只有登录失效（`unauthorized`、`session_revoked`、`device_mismatch`）才让网页回到登录页。

### 4.2 角色与二次验证

- `users.role`：`user` / `admin`。第一个管理员由命令行产生：`user create <名> --admin` 或 `user promote <名>`；网页上与命令行都不能取消最后一个管理员，网页上不能降级、禁用或删除自己。
- 管理接口要求：管理员角色、来源地址在 `admin_allow` 内（为空则不限）、开启 TOTP 时本次登录已通过第二步（`access_tokens.mfa_at`）。
- TOTP（RFC 6238，30 秒，6 位，SHA-1，前后各容忍一步）：只有管理员可以开启（密码确认 → 扫码 → 输入验证码），同时生成 10 个一次性恢复码（只存哈希）；开启后网页登录需要第二步。命令行 `user reset-totp <名>` 或其他管理员在后台重置。客户端登录没有第二步，TOTP 保护的是管理后台。
- 管理员的敏感操作需要二次确认（删除账号需输入用户名），全部写入审计日志。

### 4.3 邀请码

- 管理员生成：可用次数（1–1000 或不限）、有效期（1 天 / 7 天 / 30 天 / 永久）、备注、注册后是否自动与邀请人成为好友。邀请码（`XXXX-XXXX-XXXX`）只显示一次，只存哈希，可作废，记录每次使用（账号、时间、IP）。
- 注册页 `/register?code=…`；用户名与密码规则同命令行。设置“邀请码注册”默认关闭；关闭时注册页与接口都不可用。

## 7. 网页远程桌面

### 7.1 浏览器即设备与权限

见 §4.1。网页主控的权限与客户端完全相同（本账号设备全部、好友按授权、访客与受信任设备按被控的模板与记录），再与服务器的“网页端可以使用的功能”求交集：

- 在线设置 `web_caps`（“服务器设置”页，默认是浏览器能用的全部：观看、键鼠、剪贴板、文件、声音、麦克风、批注；端口转发、关机、显示设置、诊断网页用不到，不能勾选）。只勾“观看画面”和“接收声音”即回到只看不控。
- 服务端对网页主控总是把这个上限放在主控信息 `ControllerInfo.caps_limit` 中（`session.incoming` 与 `assist.join` 都带），创建会话、好友改授权（`regrant`）时按它裁剪。
- 被控完全按服务端给的 `caps_limit` 执行，不另设按平台的上限；在 `session.incoming`、会话中的权限变更（`SESSION_PERMISSIONS`）、“允许并信任”三处按它裁剪：服务器的限制也作用于被控做主的访客与受信任会话。即使网页代码被改，也拿不到更多权限。
- 修改设置只影响之后建立的连接。

网页设备不会出现在好友的共享列表中，也不能被好友访问。

### 7.2 连接

1. 账号会话：`POST /api/v2/sessions`（本账号或好友共享、有观看权限的设备）；访客：§7.3。
2. 浏览器用入场券连实时通道：浏览器不能设置请求头，凭据放在 WebSocket 子协议里（`farwing.v2, ticket.<入场券>`，恢复时 `resume.<令牌>`），服务端选中 `farwing.v2`。
3. `session.start`：主屏（`screen_id = -1`）、跟随被控分辨率（`resolution_type = 3`）、合成光标、浏览器能解码的编码（见下）。校验被控公钥与设备 ID。
4. 与客户端相同形状的 offer：1 条音频、5 条只收视频、5 个带内建立的数据通道；本地 SDP 给 Opus 加 `stereo=1`；发出的 SDP 加 `a=x-farwing-identity`（设备密钥签 DTLS 指纹），访客另加 `a=x-farwing-pake`；验证 answer 的签名（与访客的 PAKE 绑定）。
5. 数据通道上实现对端协议中观看需要的部分：HELLO（control 通道双向）、SESSION（显示器列表、切换、画面设置）、CURSOR、POINTER（只用作指示指针）、PARTICIPANTS、PERMISSIONS、HOST_EVENT、AUDIO。
6. 画面用浏览器原生 WebRTC 解码，`<video>` 播放。多人观看时没有控制权的参与者使用 1080p · 60 FPS 的共享观影流。

被控侧的配套修改：没有 `display` 能力的会话在初始准备时不能改分辨率（`resolution_type` 2 / 4 改为 3）。

**视频编码**：浏览器按 `RTCRtpReceiver.getCapabilities` 与 `mediaCapabilities.decodingInfo({type: 'webrtc'})` 判断能接收的编码，只声明与被控注册格式一致的那一种：AV1 profile 0、H.265 Main（`profile-id=1`）、H.264 42e01f `packetization-mode=1`，都是 8 bit 4:2:0。`session.start` 的 `decoders` 与 `capability.video_codec_capability` 列出这些编码（硬件解码 `codec_impl = 32`，软件解码 37，被控据此优先选硬解的编码），HELLO 声明对应的 `video.av1` / `video.hevc` / `video.h264`。各视频轨的编码偏好依次为 AV1、H.265、H.264、RTX。被控的 AV1 注册带 `level-idx=17`，浏览器是 5，被控要求双方都有的 fmtp 键相等，所以发出的 offer 删掉 AV1 的 `level-idx`（只改发出的副本，本地描述不变）。被控的 `session.setting`（能力）给出它能编码的格式，与浏览器能解码的交集出现在“画质”菜单的“编码格式”中：自动（由被控选择，显示当前编码）或指定 AV1 / H.265 / H.264，用画面设置的 `codec_type` 切换，不需要重新协商；选择保存在浏览器里，下次连接时放在 `session.start` 画面参数的 `codec` 中，被控双方都支持时从一开始就用它（收到第一份显示器列表后仍会再发一次画面设置，与当前一致时不重建编码器）。自动画质下被控报告的档位按被控设备记在浏览器里，下次从这一档开始（`auto_quality`），与原生客户端一样；访客页面打开时就预先建好访问码 SPAKE2 计算用的基点倍数表。被控设定了首选编码时菜单只显示该提示（被控的首选优先于主控的选择）。

### 7.3 访客观看（无需账号）

- 公开页面 `/visit`：短号或设备 ID，以及访问码或“请对方确认”。从收藏进入时自动填入短号。
- 已登录的浏览器以账号身份请求；未登录时取得游客身份（`POST /api/v2/guest/session`，需要开启游客功能）。
- 访问码校验在浏览器中用 SPAKE2 完成：TypeScript 实现与 Rust `spake2` 0.4 相同的算法（Ed25519 群、对称模式、身份串 `farwing-assist-v2`、两个码槽），Rust 生成的测试向量保证逐字节一致；访问码不离开浏览器，错误的访问码在本地由密钥确认发现。
- 浏览器的访客权限是被控的访客模板与服务器网页上限的交集。被控的确认弹窗按交集写“网页端请求查看画面并控制键鼠”或“网页端只能观看和收听”；“允许并信任”时记录的权限同样取交集，信任过的浏览器以后无需访问码与确认。

### 7.5 浏览器要求

Chrome / Edge 120+、Firefox 128+、Safari 17+（WebRTC、数据通道、H.264 解码；能接收 AV1 或 H.265 的浏览器自动使用；WebCrypto Ed25519 不可用时自动改用纯 JS 实现）。目前只在 Chrome 中验证过（含手机宽度的布局：窄屏时观看页工具栏分两行，菜单与面板占满宽度）。

### 7.6 风险与验证

最大的不确定点是被控对 offer 形状与 HELLO 的隐含要求。阶段 0 的技术验证一次通过（浏览器连本机被控出画面），简报列出的硬性条件（UUID 的 attempt、`screen_id = -1`、非空解码能力、签名、带内数据通道、control 通道上的双向 HELLO、不带 `fct`）均已满足，不需要为网页另设“观看者档案”。

### 7.7 控制（阶段 6）

按 PERMISSIONS 中的实际授权显示功能；没有的功能不出现。

| 功能 | 说明 |
| --- | --- |
| 控制权 | 有键鼠权限时出画面后自动请求控制权（多人时不自动抢，由用户点“开启键鼠控制”）；先到先得，他人控制时按钮显示“某某 正在控制”；拿到控制权后才转发输入；被收回时提示；网络恢复后自动重新获取。用户关掉控制后，之后的会话不再自动请求 |
| 键盘 | 焦点在画面上时按物理键（`KeyboardEvent.code` → HID usage）转发，含重复、锁定键状态（CapsLock / NumLock / ScrollLock 与被控对齐；macOS 不对齐）、按住时 50 ms 心跳；失去焦点或切走标签页时按“普通键 → 修饰键 → 鼠标键”的顺序全部松开。控制时 F / M / S 快捷键交给被控 |
| 全屏键盘锁定 | 全屏且控制时调用 Keyboard Lock（Chromium），Win、Alt+Tab、Esc 等交给被控，提示“按住 Esc 退出全屏” |
| 特殊键菜单 | Ctrl+Alt+Del（需要被控以服务方式运行）、Win、Win+R、Win+E、Alt+Tab、Alt+F4、Esc、PrintScreen；锁定、任务管理器、显示桌面、任务视图；“输入文字…”（经剪贴板粘贴，适合手机与非 ASCII） |
| 鼠标 | 绝对定位：按画面在窗口中的位置换算到被控屏幕，按键拖出画面时钳在边缘；被控光标由本地显示（被控停止把光标合成进画面）；被控光标隐藏时（被控没有鼠标、程序隐藏了光标）本地显示普通箭头，保证能看清指向。相对移动：锁定指针（Esc 退出，回到绝对定位），被控合成光标。左、中、右、侧键，滚轮按 1/120 格换算；控制通道积压时合并移动 |
| 触屏与笔 | 被控声明了 `touch` 时默认发送原生触摸（多指、压力，被控上用 Windows 合成触摸注入），“特殊键与鼠标”菜单可改为模拟鼠标；被控不支持时：轻点 = 左键，长按 = 右键，拖动 = 左键拖动，双指移动 = 滚轮，双指轻点 = 右键。被控声明了 `pen` 时笔按笔发送（压力、倾斜、旋转、笔杆键、橡皮擦、悬停），否则当作鼠标 |
| 剪贴板 | 文本（Windows Unicode 文本格式）。自动同步（默认开，控制时）：页面获得焦点时把本机文字发给被控，被控复制的文字写入本机剪贴板（页面没有焦点时显示“点击复制到本机”）；手动“发送本机剪贴板 / 获取对方剪贴板”。32 KiB 以上经 bulk 通道分块传输。多人时被控只与控制者自动同步 |
| 文件 | 文件面板：浏览被控的磁盘与常用文件夹；上传文件或整个文件夹到当前文件夹（根目录时上传到被控用户的“下载”），重名的文件与顶层文件夹自动改名（“名称 (1)”），空文件夹也会建立；下载文件或整个文件夹（Chromium：文件边收边写到用户选择的位置，文件夹写进用户选择的目录下的新文件夹；其他浏览器在内存中拼装，文件夹打包成 ZIP，限 1 GB）；拖放文件或文件夹到画面即上传到“下载”；进度与取消 |
| 批注 | 有批注权限时“批注”菜单：开启后指针在画面上画画，不再控制键鼠；画笔（6 种颜色、3 种粗细，边画边以 30 ms 一段发出，本地先显示正在画的一笔）、激光笔（拖尾在被控上淡出）、撤销上一笔、清空、白板（在被控屏幕上铺白底）；关闭批注时被控清除全部笔迹。笔迹画在被控屏幕上，所有参与者都能在画面中看到 |
| 麦克风 | 浏览器麦克风（回声消除、降噪、自动增益）送进被控的 Farwing 虚拟麦克风，128 kbit/s；被控上有程序使用虚拟麦克风时才发送；被控没装虚拟声卡时提示 |

实现要点：音频收发器从第一次 offer 起就是 `sendrecv`，并确认音频段带 `a=ssrc`（被控只为声明了 SSRC 的段接收；浏览器没写时用一条静音轨生成 offer）；HELLO 声明 `clipboard`、`files`、`audio.microphone`；CLIPBOARD 与 FILE 消息按 MORE 分片发送与拼接；TRANSFER / FLOW 按累计信用控制（上传遵守被控给的信用，下载写入后再给信用）。服务端的页面权限策略允许本站使用麦克风与剪贴板。

## 8. 数据与接口

schema 4（数据库结构的当前版本；新数据库直接按它创建，没有迁移，其他版本的数据库拒绝启动）：

| 表 / 列 | 内容 |
| --- | --- |
| `users.role` | `user` / `admin` |
| `users.totp_secret`、`totp_enabled_at`、`totp_recovery` | TOTP 密钥、开启时间与恢复码哈希 |
| `access_tokens.mfa_at` | 这次登录通过第二步的时间（网页会话没有单独的表，网页登录就是平台为 `web` 的设备登录） |
| `invites`、`invite_uses` | 邀请码（哈希、创建者、备注、次数、过期、作废、自动加好友）与使用记录 |
| `settings` | 在线可改的设置（键值），覆盖配置文件 |
| `update_announcements` | 更新公告（只在网页端或管理接口中管理） |
| `audit_log` | 时间、操作者、类型、对象、详情、结果、IP |

接口（全部签名，网页与客户端共用一套认证；新接口都在 `/api/v2` 下）：

- 公开：`GET /api/v2/web/info`（实例名、版本、地址、证书指纹、是否开放注册与游客、客户端下载）。
- 登录与注册：`POST /api/v2/auth/login`（既有）、`POST /api/v2/auth/totp`、`POST /api/v2/auth/register`、`POST /api/v2/auth/logout`。
- 本人：`PATCH /api/v2/me`、`GET /api/v2/me/security`、`POST /api/v2/me/password`、`POST /api/v2/me/totp/{setup,enable,disable}`；设备、好友、授权、收藏、登录沿用客户端接口。
- 管理：`/api/v2/admin/{overview, users[/{id}[/password | /totp/reset]], invites[/{id}[/uses]], devices[/{id}[/disconnect]], sessions[/{id}], updates[/{id}], settings, audit}`。`PUT …/settings` 须带全部在线设置（包括 `web_caps`，没有默认值）。
- 观看与控制：`POST /api/v2/sessions`、访客 `POST /api/v2/assist/join` 与 `…/accept`（既有），实时通道新增子协议入场；`ControllerInfo` 新增可选字段 `caps_limit`。

测试：服务端集成测试 `server/tests/web.rs`（管理员角色与 IP 白名单、TOTP 与恢复码、最后一个管理员与自身保护、账号管理与审计、邀请码次数与作废、在线设置与更新公告、网页登录提前过期与网页端能力上限、错误密码不算登录失效、浏览器子协议入场、页面安全头）；前端单元测试（Vitest：对端协议编解码与两份简报中的字节示例——输入、控制权、麦克风、剪贴板、文件、分片——SPAKE2 测试向量、设备 ID 推导、DTLS 指纹）；协议 crate 的 `caps_limit` 测试（上限只来自服务端，原生主控不带上限）。
