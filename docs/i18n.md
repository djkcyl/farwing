# 界面语言（i18n）

客户端与网页端的界面文字有简体中文（`zh-CN`）和 English（`en`）两种。默认跟随系统（客户端按 Windows 显示语言，网页端按浏览器语言；中文系统用简体中文，其他语言用 English），可以在设置中改。

不翻译：日志（`tracing::*`）、命令行输出、协议中的值与标识、诊断包内的说明文件。

## 客户端（Rust）

`src/i18n/`：每个区域一个模块，一个结构体，每条文字一个字段；同一文件中并排写两种语言的常量 `ZH_CN` 与 `EN`。编译器保证两种语言条目一致、参数一致。

```rust
pub(crate) struct Center {
    pub devices_title: &'static str,
    /// 设备名、台数
    pub found: fn(&str, usize) -> String,
}
pub(crate) const ZH_CN: Center = Center {
    devices_title: "设备",
    found: |name, count| format!("{name} 等 {count} 台"),
};
pub(crate) const EN: Center = Center {
    devices_title: "Devices",
    found: |name, count| format!("{name} and {count} more"),
};
```

使用：`crate::i18n::t().center.devices_title`；带参数的：`(crate::i18n::t().center.found)(&name, count)`。`t()` 只是一次原子读取，可以在每帧调用；不要缓存取到的文字（切换语言后要立即生效）。

- 字段名用英文 snake_case，按含义命名（`no_trusted_devices`），不按中文直译。
- 常用词（确定、取消、关闭、保存、在线、离线……）在 `common.rs`，直接用，不要在别的区域重复定义。
- 常量数组里的文字（`const LABELS: [&str; N]`）改为函数或 `match`，在用到时取当前语言。
- 一段文字在一个进程生成、在另一个进程或另一台电脑显示时（后台服务的状态、被控发给主控的提示、服务端错误），传代码，在显示的一方翻译。服务端错误按 `ErrorCode` 与 `details.reason` 在 `errors.rs` 中翻译。

## 网页端（TypeScript）

`server/web/src/i18n/`：中文对象是类型的来源，英文对象必须实现同一类型；带参数的文字写成函数。

```ts
const zh = { devices: { title: '设备', found: (name: string, n: number) => `${name} 等 ${n} 台` } }
export type Messages = typeof zh
const en: Messages = { devices: { title: 'Devices', found: (name, n) => `${name} and ${n} more` } }
```

组件中 `const t = useT()` 后用 `t.devices.title`、`t.devices.found(name, n)`。语言保存在 `localStorage`；登录、注册、访客页右上角和登录后的侧边栏可以切换。服务端错误按错误码与 `reason` 翻译（`i18n/errors.ts`），审计日志详情由 `i18n/audit.ts` 显示。

## 跨进程与跨设备的文字

- 后台服务（服务模式）为设备中心生成的状态与错误，使用设备中心的语言：设备中心每次读取状态时带上自己的语言。
- 被控拒绝控制权、拒绝直连（无人应答、锁屏、程序未打开）时只发代码，由主控按自己的语言显示。
- 服务端错误只发 `code` 与 `details.reason`，各端自己翻译。
- 设备之间的其他提示同样只发代码或原因键，由显示的一方翻译：被控事件（显示设置由谁修改只发昵称）、音质与显示设置被拒绝的原因、端口转发结果、文件传输错误码、剪贴板与拖放被拒绝的原因、远程诊断的进度步骤与拒绝原因。原因键定义在各自的协议模块中（如 `audio_control::reason`、`clipboard::wire::reason`、`stream_control::wire::setting_reason`、`drag_drop::reason`）。
- 对方的原始错误文字（操作系统错误、路径等）只写入对方的日志；文件传输的 I/O 与协议错误例外，会附在本方的说明之后。
- 对方文件根目录中的磁盘与常用位置（文档、桌面……）按本方语言命名。

## 文案规范

中文：

- 只写标签、数值、状态、操作。不写页面说明、功能原理、操作教程、空状态里的指引、解释性的悬停提示。
- 用中性、规范的软件用语，不用口语、不装作人在说话：写“无法连接服务器”，不写“暂时连不上服务器”；写“暂无受信任设备”，不写“还没有受信任的设备”；不用“TA”“呢”“吧”“一下”“别担心”“试试”。
- 常用格式：无法连接服务器、连接失败：{错误}、已断开、暂无…、未…、正在…、已保存、已开启。提示和错误只写一句事实。
- 删除等不可撤销的确认框：标题是问题（“删除设备？”），正文最多一句后果（“删除后无法恢复”）。

English:

- Sentence case for labels and buttons (“Sign in”, “Trusted devices”); no trailing period on labels, buttons, short states and one-line messages.
- Plain, neutral wording: “Can't connect to the server”, “No trusted devices”, “Saved”, “Couldn't save: {error}”, “Connecting…”.
- Keep product and technical names as they are (Farwing, FPS, Mbps, H.264, UPnP).
- Same content as the Chinese text, no extra explanation.
